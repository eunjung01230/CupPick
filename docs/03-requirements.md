## 0. 역할과 읽는 법

이 문서는 **누가 무엇을 할 수 있어야 하는지**를 정의한다. 실행 방법은 04-features.md, 예외·기간·한도의 원문은 02-workflow.md를 따른다. 모든 R은 현재 MVP 또는 그 공개 운영에 필요한 요구다. 후순위 기능은 00-backlog.md에만 두며 이 표에서 미리 구현하지 않는다.

- 유형: 기능(행동·결과), 데이터(구분·보존해야 할 의미), 제약(항상 지켜야 할 한계).
- U1 사용자, C1 시스템, O1 운영 담당자. O1 요구는 별도 사용자용 관리자 화면을 뜻하지 않는다.
- N1~N6는 01의 사용자 결과, WF는 02의 흐름이다. `02 §`는 02의 장·절을 뜻한다.
- 각 번호는 고정한다. 삭제·변경 시 재번호를 매기지 않고 00에 근거를 남긴다.
- 모든 요구는 개발 완료의 판정 대상이다. 핵심 사용자 화면과 기록 보호/운영 요구를 모두 같은 화면에 노출하지 않는다.

## 7. 범위·우선순위 경계

핵심 이용 경로는 **F01~F08로 탐색·등록 → F10/F19로 갱신 → F25/F05로 매장 선택 → F27로 사용 기록**이다. 만료 묶음·전환·복구는 필요한 사용자에게만 보이는 보조 흐름이다. 임시 작성·동시 수정·중복 방지는 사용자의 관리 항목이 아니라 공통 동작이다.

다음은 현재 요구사항이 아니다. OCR 자동 인식, 앱 알림 자동 읽기, 브랜드 공식 API 자동 연동, 자동 스탬프 적립, 자동 쿠폰 사용·차감, 결제, 리뷰, 평점, 피드, 친구/소셜, 앱 내부 도보 길찾기, 추천 순위·새로운 추천 알고리즘, 행사 자동 수집, 개인카페·타 업종, 금액권 부분사용 잔액, 추가 브랜드. 단, 대상 브랜드의 보유 행사 쿠폰을 단일 쿠폰으로 직접 기록하는 R30은 현재 범위다.

1차 지원 브랜드는 01 §8.3의 7개다. 쿠폰 사용 완료는 1차에서 사용자가 직접 처리하며 공식 앱과 자동 연동하지 않는다(R43).

정책은 [05-policy.md](05-policy.md)의 POL01~POL26, 저장 항목은 [06-data.md](06-data.md)의 D01~D22로 정의했다. 요구사항의 연결 F번호를 따라 06의 기능→정책→데이터 표까지 추적할 수 있다. 01의 P1~P5는 문제 번호이며 정책 번호가 아니다.

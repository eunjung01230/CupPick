## 0. 문서의 역할과 결정 원칙

이 문서는 누구의 어떤 문제를 해결하는지와 초기 제품의 경계를 정의한다. 워크플로·요구사항·기능·정책·데이터·디자인의 기준으로 사용한다.

- **확정 방향:** 후속 사용자 합의와 위임 판단을 포함한 현재 제품 결정이다. 각각의 근거는 00-backlog.md에 구분한다. 최초 대화 전체를 복원했거나 시장에서 검증했다는 뜻은 아니다.
- **가설:** 사용자 조사로 검증해야 하는 행동·불편·효과다.
- **현재 기준선:** 확인 가능한 v1.4 문서·후속 직접 대화와 v2.0 위임 결정을 이어받는다. 초기 대화 전체 원문은 확보하지 못했으며, 기억 요약을 최초 확정의 증거로 확대하지 않는다. 판단 근거·변경 이력은 00-backlog.md를 먼저 읽는다.
- **출시 검증:** 브랜드 실제 정책, API 계약·성능, 플랫폼 심사는 사실·구현 검증 대상이다. 문서 확정이 검증 완료를 뜻하지 않는다. 충족하지 못하면 관련 자동 기능을 보류하거나 출시 범위를 변경 이력과 함께 재검토한다.
- 새로운 요구사항은 본 기준선에 대한 변경으로 기록한다. 이미 공통 규칙으로 해결한 예외를 다시 질문하지 않는다.
- 기존 P·N·H·Q 번호는 유지한다. 삭제한 번호를 다른 의미로 재사용하지 않는다.
- 이 문서의 기능 요약은 범위 확인용이다. 후속 문서에 상세 조건을 정의하되, 이미 확정된 범위를 임의로 바꾸지 않는다.

## 1. 서비스 정의

### 1.1 이름과 제공 형태

- 제품명: **CupPick**. 명칭 사용 가능 여부는 공개 출시 전 확인한다.
- 첫 출시 목표: **Android·iOS 앱 모두 지원**.
- 개발 프레임워크·지도 공급 계약·배포 구성은 구현 설계에서 선정한다. 이 문서는 특정 기술을 지원 확인 없이 확정하지 않으며 02-workflow.md 19장의 출시 조건을 적용한다.

### 1.2 한 줄 정의

> 현재 위치 또는 사용자가 지정한 위치 주변의 카페와 개인 보유 스탬프·쿠폰·만료 정보를 함께 제공하여, 혜택의 사용 조건을 확인하고 이용할 카페를 선택하도록 돕는 서비스.

### 1.3 핵심 가치

사용자는 “오늘 커피 어디서 마시지?”라는 순간에 주변 매장과 자신의 혜택을 함께 확인한다. 만료 전 알림을 통해 잊고 있던 혜택을 알아차리고 사용할 매장을 찾을 수도 있다.

MVP는 정보를 비교한 사용자가 직접 선택하는 방식이다. 카페 추천·추천 순위는 확장 기능이다.

## 2. 대상 사용자

### T1. 핵심 타깃

거주지·학교·직장 등 일상적인 생활권에 카페 선택지가 여러 곳 있고, 단골 카페가 있으면서도 위치·가격·혜택·상황에 따라 여러 카페를 반복적으로 이용하는 사람.

- 여러 생활권을 이동하는 것은 필수 조건이 아니다.
- 한 생활권에서 여러 카페를 번갈아 이용하는 사람도 포함한다.
- 연령·직업보다 실제 이용 행동을 우선한다.

### T2. 초기 집중 대상

T1 중 저가·중저가 커피 프랜차이즈 여러 브랜드를 이용하며 스탬프·쿠폰 혜택에 관심이 있는 사용자.

**가설:** 여러 브랜드 혜택을 보유하고 이를 실제 선택에 활용하려는 사용자에게 문제가 더 뚜렷하다.

### T3. 우선순위 판단의 경계

핵심 설계는 T1·T2를 기준으로 한다. 분위기·사진·좌석·리뷰 중심의 카페 탐색은 초기 해결 범위에 포함하지 않는다. 이는 특정 사용자의 가입을 제한한다는 뜻이 아니다.

## 3. 문제가 발생하는 상황

다음은 설명용 가상 상황이며, 실제 인터뷰·관찰 사례가 아니다.

**상황 A — 구매 전 비교**

사용자가 학교 주변에서 커피를 사려 한다. 단골을 포함한 여러 매장이 있지만 어느 브랜드에 쿠폰이 있는지, 무엇이 곧 만료되는지 기억하지 못한다. 앱을 각각 확인하거나 평소 가던 곳을 선택한다.

**상황 B — 만료 전 활용**

사용자가 보유 쿠폰의 만료가 임박했음을 알게 된다. 현재 위치나 방문 예정 지역에서 그 쿠폰을 사용할 매장을 찾고 싶다.

**상황 C — 사용 조건 확인**

브랜드 쿠폰을 보유하고 있지만 특정 매장에서 사용할 수 있는지 명확하지 않다. 쿠폰 종류·매장 제한·적립 이력 조건 등을 확인해야 한다. 특정 브랜드에 어떤 조건이 적용되는지는 별도 검증한다.

## 4. 핵심 문제

아래 P1~P5는 제품이 검증하려는 문제 가설이다.

| 번호 | 문제 | 사용자가 겪는 불편 |
| --- | --- | --- |
| P1 | 위치와 개인 혜택 정보의 분리 | 방문 가능한 매장과 자신의 혜택을 한 번에 비교하기 어렵다. |
| P2 | 여러 브랜드 혜택의 확인·갱신 부담 | 개수·쿠폰·만료일을 기억하고 최신으로 유지하는 데 수고가 든다. |
| P3 | 혜택 활용 기회의 누락 | 구매 전에 혜택을 떠올리지 못하거나 만료 시점을 놓칠 수 있다. |
| P4 | 정보를 선택에 연결하기 어려움 | 거리·혜택·사용 조건을 사용자가 직접 종합해야 한다. |
| P5 | 보유와 사용 가능 여부의 혼동 | 쿠폰이 있어도 방문하려는 매장에서 쓸 수 있는지 별도 확인이 필요하다. |

### 핵심 문제 문장

> 여러 카페를 반복 이용하는 사람은 주변 매장과 자신의 보유 혜택·만료일·사용 조건을 함께 확인하기 어려워, 카페 선택과 혜택 관리에 번거로움을 겪고 활용 기회를 놓칠 수 있다.

## 5. 현재 대안과 검증할 한계

아래는 조사 대상의 분류이며 경쟁 서비스의 기능 부재를 단정한 분석이 아니다.

| 대안 | 해결하려는 일 | 확인할 질문 |
| --- | --- | --- |
| 지도·장소 검색 | 주변 매장 조회 | 개인의 여러 브랜드 혜택까지 연결되는가? |
| 브랜드 공식 앱 | 해당 브랜드의 정확한 혜택 확인 | 여러 브랜드를 비교할 때 얼마나 번거로운가? |
| 쿠폰 보관·알림 수단 | 만료일 관리 | 실제 방문·사용 가능한 매장과 연결되는가? |
| 기억·메모·캡처 | 개인 정보 기록 | 정보가 최신이며 필요할 때 쉽게 찾을 수 있는가? |
| 단골 매장 선택 | 선택 시간 단축 | 다른 혜택을 확인할 필요를 실제로 느끼는가? |

CupPick은 공식 앱의 적립·결제 시스템을 대체하지 않는다. 현재 잔액과 쿠폰 발급·사용 사실은 공식 앱 등 원래 제공처에서 확인한다.

## 7. 대표 페르소나

**가설적 사례:** 23세 대학생. 집·학교·아르바이트 장소 주변에서 주 4~6회 커피를 구매한다. 단골이 있지만 거리·가격·혜택에 따라 다른 카페도 이용한다. 여러 브랜드의 스탬프·쿠폰 상태를 기억하지 못하며, 각 앱을 반복해서 확인하는 일을 번거롭게 느낀다.

> “내가 가진 혜택과 쓸 수 있는 주변 카페를 함께 보고 싶다. 관리하는 일까지 복잡하지 않았으면 좋겠다.”

나이·직업·구매 횟수·복수 생활권은 설명용 속성이며 이용 자격이 아니다.

## 8. 초기 제품 범위

### 8.1 확정된 MVP 범위

| 영역 | 범위 요약 |
| --- | --- |
| 플랫폼·계정 | Android·iOS. 구글·네이버·카카오 로그인. 제공자별 별도 계정, 이메일 일치로 자동 통합하지 않음 |
| 지도·위치 | 현재 위치 또는 직접 지정 위치. 앱 내 매장 위치·도보 거리·예상 시간, 외부 지도 길찾기. 도보 30분을 기본 탐색 범위로 하며 범위 확대·지정 매장 직접 조회 허용 |
| 둘러보기 | 비로그인 기본 지도·목록·매장명·브랜드·이동 정보. 매장 상세·개인 혜택은 로그인 필요 |
| 등록 선택 | 혜택 등록·선호 브랜드 설정은 강제하지 않음. 미등록과 확인된 0개 구분 |
| 브랜드 구조 | 브랜드·프로그램·용도·적립 범위별 잔액 분리. 매장 전용은 지점별 분리, 확인된 정책으로 필요한 선택만 제공 |
| 스탬프 | 적립분 추가·현재 잔액 맞추기·숫자 확인·구성 변경 구분. 구성 불명확 시 영향 범위의 자동 차감·알림 보류 |
| 쿠폰 전환 | 실제 발급 확인 후 쿠폰 기록과 아직 반영되지 않은 스탬프 차감만 함께 저장. 선택 교환·복수 쿠폰을 수용하고 중복 차감 방지 |
| 쿠폰 조건 | 사용 가능 매장을 우선 등록. 일부/전체 목록 구분. 모르면 미확인, 과거 적립 이력 재입력 강제 없음 |
| 만료 정보 | 확인된 날짜 / 정책·발급일 등에 따른 예상 날짜 / 미확인 / 확인된 기간 제한 없음 구분. 사용자에게 예상 날짜 확정을 강제하지 않음 |
| 만료 정리 | 확인된 날짜·유효한 구성·모든 처리 보류 해소인 스탬프만 자동 차감. 예상 날짜는 실제 만료 확인 후 처리. 등록한 만료 정보 기준 표시 |
| 내 혜택 | 브랜드 카드에 잔액·쿠폰 수·임박 정보 요약. 만료 임박순/선호 브랜드순 선택 기억. 거리 표시·거리 정렬 없음 |
| 지도 연결 | 스탬프는 주변 적립 매장, 쿠폰은 주변 사용 매장으로 연결. 가능·미확인·불가와 확인 근거를 목적별 표시 |
| 캡처 | 선택적 첨부·조회·교체·삭제 및 등록 권장. 확인 보조용이며 OCR·공식 사용 수단 아님 |
| 알림 | 날짜를 알거나 계산할 수 있는 혜택의 D-3·당일 한국시간 오전 8시 묶음 안내. 예상 기준 명시. 자동 정리 결과도 오전 8시 묶음 안내 |
| 기록 보호 | 사용 취소·전환 취소·자동 차감 복구. 삭제 항목은 60일 휴지통 후 영구 삭제 |
| 안정성 | 중복 저장·차감 방지, 전환 동시 저장, 동시 수정 충돌 보호, 실패 시 입력 유지 |
| 오프라인·임시 작성 | 마지막 혜택 기록 조회. 변경 저장은 온라인. 기기·계정별 임시 작성, 저장 전 혜택·알림 미반영 |

상세 조건과 예외, 보관·알림·출시 기준은 02-workflow.md를 따른다. 기술 선정은 확정된 제품 행동과 출시 검증 조건을 만족해야 한다.

### 8.2 책임 범위와 확장

- CupPick의 쿠폰 생성·사용 완료는 **관리 기록의 변경**이다. 공식 쿠폰을 발급하거나 사용 처리하는 행위가 아니다.
- 공식 잔액의 실시간 동기화는 MVP에서 제공하지 않는다.
- **우선 확장:** OCR 및 앱 알림 기반 등록·갱신. 운영체제별 가능 범위는 별도 확인하며 동일 기능을 보장하지 않는다.
- **그 밖의 확장:** 즐겨찾기 매장, 계정 연결, 앱 내부 도보 경로, 카페 추천, 실질 혜택가치 비교 고도화, 행사 통합, 동선 기반 선택, 지점별 맛 정보, 개인카페, 다른 업종.
- 주문·결제·카페 SNS는 현재 합의된 MVP 기능에 포함되지 않는다.

### 8.3 지원 브랜드와 출시 범위

수동 기록 지원 13개 브랜드: 매머드, 우지, 빽다방, 메가MGC커피, 컴포즈, 백억, 카페봄봄, 더벤티, 바나프레소, 모리커피, 텐퍼센트, 하삼동, 이디야.

모든 대상 브랜드의 수동 스탬프·쿠폰 등록을 허용한다. 정책 기반 만료 계산·교환 제안은 해당 프로그램·쿠폰 종류의 적용 정책이 확인된 범위에서만 제공한다. 실제 발급을 확인한 쿠폰과 공식 현재 잔액은 공통 정책이 없어도 직접 기록할 수 있다. 규칙을 모르면 교환 개수나 차감 순서를 추정해 확정하지 않는다.

매장 조건은 서비스가 검토한 공식 공통 정책 또는 사용자가 자기 쿠폰·공식 화면에서 확인한 개별 조건으로 표시한다. 개인 조건은 그 개인 기록에만 적용한다. 근거가 없거나 충돌하면 해당 조건만 미확인으로 남긴다.

파일럿은 **성남 서현역 중심 도보 30분 생활권**, 목표 **20명·14일**을 운영 기본값으로 사용한다. 이는 사용자의 최초 지역 요구가 아니라 v2.0에서 위임으로 정한 검증 계획이다. 이는 실행 계획이며 사용자 수요나 매장 데이터 확보를 이미 검증했다는 뜻은 아니다. 02-workflow.md 19장의 품질·반복 이용 기준을 통과하면 전국으로 동시에 공개 범위를 넓힌다. 전국 공개도 모든 매장·정책의 완전한 수록을 뜻하지 않으며 제공 범위와 조회 실패를 구분한다.

MVP는 지정 브랜드로 탐색한다. 보유한 행사·기타 쿠폰의 수동 기록은 포함하지만 브랜드 행사를 자동 수집·추천하는 기능은 포함하지 않는다. 금액권 부분 사용 잔액 관리·기프티콘 전용 연동은 후순위이며, 현재 쿠폰은 단일 사용 상태로 관리한다. 가격대는 타깃 설명에 사용하며 실제 메뉴 가격 수집·가격대 자동 필터는 포함하지 않는다.

## 9. 정확성·사용성의 기본 원칙

1. **보유와 사용 가능을 분리한다.** 쿠폰이 있다는 이유만으로 특정 매장에서 사용 가능하다고 표시하지 않는다.
2. **적립과 쿠폰 사용 범위를 분리한다.** 브랜드 통합 적립·매장별 적립과 쿠폰의 공통·지정·조건부 사용은 별개다. 적립 제외·사용 제외도 구분한다.
3. **브랜드 규칙을 고정하지 않는다.** 모든 브랜드를 ‘10개 완성’으로 가정하지 않는다. 규칙·출처·적용 시점을 관리하고 변경 가능하게 설계한다.
4. **모르는 정보는 구분한다.** 혜택 미등록, 확인된 0개, 사용 조건 미확인, 만료일 미확인을 섞지 않는다.
5. **등록은 선택, 필요한 입력은 최소화한다.** 알 수 없는 내용은 미확인으로 저장한다. 미확인 날짜와 계산 근거가 있는 예상 날짜를 구분하며, 예상 날짜는 표시 후 알림에 활용할 수 있다.
6. **마지막 확인 시점은 실제 확인을 뜻한다.** 화면 조회·캡처 첨부만으로 최신성이 검증된 것으로 처리하지 않는다.
7. **실제 만료일을 우선하되 자동 계산을 허용한다.** 알려진 발급·적립일과 확인된 적용 정책으로 예상 날짜를 계산해 저장한다. 등록일을 발급일로 간주하지 않고 월을 일수로 일괄 환산하지 않는다. 확인된 날짜만 자동 만료 정리에 사용한다.
8. **확인 수준에 맞게 만료 정리한다.** 확인된 날짜의 유효한 묶음만 자동 차감하고 내역·안내를 남긴다. 예상 날짜는 사용자 확인 후 차감하며 미확인은 자동 차감하지 않는다. 수동 변경은 잔액에 반영하고 내역을 남기되 별도 자동 정리 알림을 보내지 않는다.
9. **전체 잔액과 세부 구성을 분리한다.** 현재 잔액은 즉시 저장할 수 있다. 숫자 확인과 묶음 확인을 분리한다. 구성 불일치 시 영향받은 묶음의 만료 알림·자동 차감을 보류하며, 대상을 특정하지 못하면 해당 잔액의 영향 가능한 기존 묶음 전체를 보류한다. 상세 입력을 즉시 강제하지 않고 중복 차감을 방지한다.
10. **쿠폰 전환 기록은 실제 발급 확인을 거친다.** 현재 잔액 맞추기에는 추가 전환·차감을 적용하지 않는다. 전환 확인 중인 수량은 만료 자동 차감을 보류한다. 잘못된 전환 기록은 연결된 차감·원래 만료 조건을 함께 평가해 취소한다. 정확한 재구성이 불가능하면 공식 현재 잔액으로 맞춘다.
11. **입력 부담을 통제한다.** 공통 화면을 재사용하며 과거 스탬프 전체 내역을 MVP의 일괄 필수 입력으로 요구하지 않는다. 쿠폰별 사용 조건을 기록하는 방향으로 한다.
12. **복구와 상태 변경을 구분한다.** 만료·사용 완료·휴지통은 서로 다르다. 내역 삭제·복원은 잔액을 바꾸지 않는다. 만료 정보 삭제는 수량을 유지하며 날짜만 미확인으로 바꾼다. 스탬프 등록 삭제는 해당 잔액·묶음만 제거하고 발급 쿠폰은 유지한다. 사용자 삭제 항목은 휴지통에서 60일간 복원할 수 있다. 복원 시 만료일·사용 상태를 반영하며, 휴지통의 혜택은 알림·혜택 비교에서 제외한다.
13. **실패를 정상 정보로 표시하지 않는다.** 조회 실패와 결과 없음, 오래된 기록과 최신 확인값을 구분한다.

## 10. 조사·검증 상태

### 10.1 브랜드 정책 검증 경계

기존 조사에서 적립 기준·적용 시점·프로그램·용도·매장 예외를 구분해야 할 필요가 발견됐다. 이번 문서는 브랜드 최신 약관을 재검증한 보고서가 아니다. 과거 조사에 등장한 특정 수치를 현재 자동 계산 규칙으로 옮기지 않는다.

정책 원문 URL·적용 대상·시행일·확인일·버전·검토 담당자를 별도 정책 데이터에 기록한다. 개인 쿠폰 확인은 그 쿠폰에 대한 근거로 허용하고 브랜드 전체 정책 검증과 구분한다. 운영·오류 대응은 02-workflow.md 16장, 출시 검증은 19장을 따른다.

## 11. 현재 범위와 근거 관리

현재 제품 행동은 이 문서와 02-workflow.md를 따른다. 과거 Q1~Q24의 종료 내역·후순위·검토 결과·위임 결정 출처는 [00-backlog.md](00-backlog.md)에 보관한다. 보관된 옛 문구를 현재 기능으로 재도입하지 않는다.

현재 잔액·만료 정보·지도 연결이라는 핵심은 유지한다. 상세 구성·자동 차감·복구는 기록 정확성을 위한 보조 동작이며 첫 등록에서 상세 이력을 모두 요구하지 않는다. 최초 방향과 일치 여부는 **확보된 자료 범위에서 일치**, 초기 대화 전체의 완전 일치는 **검증 불가**로 구분한다.

## 12. 후속 문서와 변경 관리

- **워크플로:** 탐색·로그인·등록·갱신·쿠폰 전환·알림 진입·사용·복구의 사용자 행동과 분기.
- **요구사항·기능:** N1~N6와 연결하고, 본 문서 8장의 범위를 구체화.
- **정책:** 브랜드 규칙·미확인 처리·만료·중복·알림·휴지통 상세 기준 및 출처.
- **데이터:** 잔액·만료 묶음·쿠폰·사용 범위·확인 시점·정책 버전·첨부·상태 관계.
- **디자인:** Figma 기본 설계 → GPT 시각 자료 → Claude Design 통합. 동일한 기능·상태 기준을 전달.
- **백로그:** OCR·앱 알림 기반 갱신을 우선 확장으로, 추천 및 기타 확장을 별도로 관리.

타깃·핵심 문제·출시 범위를 바꾸면 이유와 영향을 기록한다. 세부 구현 변경만으로 문제정의 전체를 다시 쓰지 않는다. 가설이 검증되지 않거나 반증되면 수정하며, 수정 횟수를 줄이기 위해 근거 없는 전제를 고정하지 않는다.

문서 구성은 00 후순위·변경 이력, 01 문제, 02 흐름, 03 요구사항, 04 기능, 05 정책, 06 저장 항목이다. 00~06 문서가 작성됐다. 세부 정책은 [05-policy.md](05-policy.md), 저장 항목·관계는 [06-data.md](06-data.md)를 함께 따른다. 05·06은 기존 흐름을 구체화하며 새 범위를 추가하지 않는다.

## 13. 구현 시 지켜야 할 핵심 경로

사용자는 주변 매장을 둘러보고, 잔액 숫자 또는 보유 쿠폰의 최소 정보만 등록한 뒤, 필요한 매장의 적립·사용 조건을 확인할 수 있어야 한다. 묶음 분할·사건 연결·재시도는 내부 처리다. 기존 쿠폰 연결과 충돌 안내는 해당 상황에서만 제공하며 첫 등록의 필수 단계로 추가하지 않는다.

이번 보완은 기록 오류와 막힌 복원 흐름을 해결하기 위한 것이다. 휴지통 사진의 선택 영구 삭제는 첨부 용량 관리에 한정한다. 추천·공식 연동·후기·행사 수집의 후순위는 유지한다. 사용성은 기존 파일럿 기준과 03 §8의 품질 기준으로 검증한다.

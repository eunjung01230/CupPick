## 0. 역할과 통합 원칙

핵심 목표는 **최대한 정확하지만 번거로움은 적게**다. 이 문서는 사용자 행동, 시스템 반응, 예외·복구를 정의한다. 화면의 세부 배치와 기술 구현은 후속 문서에서 다룬다.

기존 WF-01~WF-13 및 Q 번호는 유지했다. 과거 질문·방향 변경은 00-backlog.md에 정리했다. 동일한 확인·저장·알림 규칙은 각 기능에서 반복 정의하지 않고 공통 원칙을 적용한다.

이번 통합은 새로운 브랜드 정책 조사나 실제 앱 검증이 아니다. 브랜드별 수치·조건은 원문과 적용 범위를 확보한 뒤 16장의 검토 절차로 등록한다. 미확인·충돌 정책을 현재 사실로 확정하지 않는다.

## 1. 범위·행위자·상태

### 1.1 MVP와 확장

- Android·iOS 앱. 특정 생활권에서 검증 후 전국 동시 확장.
- 1차 구현 대상 7개 상위 브랜드: 컴포즈커피, 메가MGC커피, 빽다방, 더벤티, 매머드, 우지커피, 텐퍼센트커피. 브랜드 추가는 후순위다.
- 7개 모두 수동 기록 지원. 자동 계산·교환 제안은 적용 규칙을 확인한 범위에서 제공.
- 프로그램 유형은 누적형·단계 교환형·매장 조건형 세 가지다. 모든 브랜드를 10개 누적으로 가정하지 않는다. 브랜드별 값은 05 POL26을 따른다.
- 매머드는 브랜드 목록에서 하나로 표시하고 내부에서 매머드커피/매머드익스프레스를 구분한다. 잔액은 합산하지 않으며 매장 데이터도 어느 프로그램의 매장인지 구분한다.
- 매머드커피는 매장별로 스탬프를 따로 관리하고 12개·20개에서 사용자가 직접 교환한다. 서로 다른 매장의 스탬프를 합산하지 않는다.
- 우지커피·텐퍼센트커피는 매장당 3개 이상 적립한 매장에서만 쿠폰을 사용할 수 있어 매장별 적립 수량을 관리한다.
- 다른 브랜드도 별도 제도가 생기면 같은 브랜드 아래 프로그램을 추가할 수 있다.
- 수동 입력, 캡처 첨부, 혜택·지도 연결, 만료 안내, 정리·복구, 선호 브랜드 정렬은 MVP.
- OCR·다른 앱 알림 읽기는 우선 확장. 추천, 즐겨찾기 매장, 계정 연결, 앱 내부 도보 경로는 확장.

### 1.3 상태는 여러 축으로 분리

| 구분 | 상태와 의미 |
| --- | --- |
| 등록 | 미등록 / 등록됨. 미등록은 보유량 0이 아님 |
| 잔액 | 마지막으로 확인한 값 및 이후 기록상 변경. 실시간 공식 잔액을 보장하지 않음 |
| 쿠폰 생애 | 보유 / 사용 완료 / 만료 / 전환 취소. 휴지통 여부는 별도로 보관하고 복원 시 이전 생애 상태 재평가 |
| 쿠폰 표시 상태 | 기록됨 / 아직 사용 불가 / 사용 가능 / 만료 임박 / 사용 완료 / 만료. 저장하는 값이 아니라 생애·날짜 신뢰·사용 시작일에서 계산하는 화면 상태다 |
| 날짜 신뢰 | 확인된 날짜 / 예상 날짜 / 미확인 / 확인된 기간 제한 없음 |
| 매장 조건 | 사용 가능으로 확인 / 사용 여부 미확인 / 사용 불가로 확인 |
| 구성 상태 | 유효한 상세 구성 / 구성 확인 필요. 수량 일치만으로 유효함을 확정하지 않음 |
| 처리 보류 | 전환 확인 필요 / 정책 충돌 등 사유를 복수로 보관. 모든 보류 사유 해소 후 자동 처리 재개 |
| 통신·조회 | 조회 성공 / 결과 없음 / 조회 실패 / 오프라인 마지막 기록 |

매장 조건이 충족되어도 메뉴·기간·주문 방식 등 전체 조건이 충족된 것으로 단정하지 않는다. 보유와 실제 사용 가능 여부를 하나의 상태로 합치지 않는다.

`오늘 사용 가능`·`내일부터 사용 가능`·`N분 후 사용 가능`·`N일 남음`·`오늘 만료`·`만료` 같은 시간 표현은 모두 **실행 시점의 실제 한국 날짜·시각**으로 계산한다. 디자인 시안이나 예시 문서에 들어 있는 특정 날짜를 시스템 기준일로 고정하지 않는다.

## 2. 전체 이용 흐름

앱 실행 → 주변 카페 둘러보기 → 매장 상세·혜택 기능에서 로그인 → 필요한 브랜드 혜택 등록 → 내 혜택 확인 또는 지도에서 매장 비교 → 실제 공식 앱·매장 이용 → 기록 갱신.

만료 알림으로 진입하면 해당 혜택 상세·목록을 연다. 스탬프는 주변 적립 매장, 쿠폰은 주변 사용 매장으로 연결한다. 가입과 혜택 등록은 지도 둘러보기의 선행 필수 조건이 아니다.

## 3. WF-01 앱 실행·둘러보기

1. 새 실행은 현재 위치 조회를 기본으로 한다.
2. 외부 앱 전환·백그라운드 복귀·운영체제 화면 복원은 보던 조회 위치를 유지한다.
3. 현재 위치를 사용할 수 없으면 마지막 조회 위치와 기준을 표시한다. 기록도 없으면 직접 지정 안내.
4. 위치 권한 허용 여부와 관계없이 사용자가 다른 지역을 검색·지정할 수 있다.
5. 비로그인은 지도·주변 카페 목록, 브랜드·매장명, 예상 도보 시간, 기본 매장 정보, 지도 이동·확대·축소, 외부 지도 길찾기를 이용한다.
6. 개인 데이터가 필요한 다음 기능에서 로그인을 요구한다: 내 스탬프, 내 쿠폰, 혜택 등록, 내 혜택 기준의 사용 가능 여부 판정, 개인 데이터 관리(알림·선호 브랜드·휴지통·계정). 비로그인 화면에서는 혜택 판정 배지와 잔액 요약을 표시하지 않는다.
7. 혜택이 없는 첫 진입에는 주변 카페와 ‘스탬프·쿠폰 등록하기’를 제공한다. 등록을 강제하지 않는다.

‘새 실행’은 복원할 탐색 화면 없이 처음 홈을 여는 경우다. 세션·화면 복원과 일반적인 화면 전환을 새 실행으로 취급하지 않는다. 위치 조회 실패 시 직접 지정 또는 마지막 위치를 사용한다.

## 4. WF-02 위치·지도·외부 길찾기

### 4.1 조회와 이동 정보

- ‘현재 위치 기준’ 또는 ‘선택한 위치 기준’을 표시한다.
- 지역명·주소 직접 검색과 저장한 장소(‘자주 가는 곳’) 바로 선택을 제공한다. 저장한 장소의 개수 한도·관리 방법은 4.3을 따른다.
- 앱 안에는 매장 위치, 도보 거리, 예상 이동 시간을 제공한다.
- 실제 경로 선은 MVP에서 표시하지 않고 외부 지도 길찾기로 연결한다.
- 탐색 범위는 **도보 15분과 도보 30분** 두 단계다. 기본값은 15분이고 30분이 MVP 최대 범위다. 더 넓은 범위는 MVP에서 제공하지 않는다. 범위는 강제 이용 제한이 아니며 도보 시간을 확인한 후보만 범위 안으로 분류한다. 지정된 사용 매장은 거리와 무관하게 상세에서 직접 열 수 있다.
- 지도 핀은 `브랜드별 최단 1곳`과 `모든 지점` 두 가지로 표시할 수 있다. 표시 방식이며 조회 범위나 정렬을 바꾸지 않는다.
- 목록은 페이지당 20개, 추가 보기는 다음 20개를 불러온다. 아직 조회하지 않은 영역을 포함해 모든 매장을 찾았다고 표시하지 않는다. 지도 이동 후 사용자가 ‘이 지역 검색’을 누를 때 재조회한다.
- 초기 후보 검색은 조회 위치 중심 반경 3km에서 시작하되 이는 탐색 범위일 뿐 도보 시간의 환산값이 아니다. 검색 완전성은 공급자 결과 한도를 따르며 결과가 잘리면 추가 조회 안내를 표시한다.
- 도보 정보 실패 시 매장은 유지하고 ‘도보 정보 확인 불가’ 표시. 직선거리를 도보거리로 대체하지 않으며 선택한 범위 안이라고 판단하지 않는다.
- 위치 실패, 매장 없음, 매장 데이터 실패를 구분한다.
- 도보 시간은 예상치이며 실제 이동·영업·쿠폰 사용을 보장하지 않는다.

### 4.2 외부 길찾기

1. 처음 사용할 지도 앱을 선택하고 이후 선택을 기억한다. 기본 앱 변경 가능.
2. 연결 전에 출발지(조회 위치)와 도착지(선택 매장)를 보여준다.
3. ‘현재 위치에서 출발’로 변경할 수 있다.
4. 선택 앱을 열 수 없으면 다른 앱 또는 웹 지도 선택 안내.
5. 지정 출발지·도착지 전달 지원 여부는 실제 연결 수단 검증이 필요하다. 지원하지 않는 방식으로 조용히 다른 출발지를 전달하지 않는다.

### 4.3 저장한 장소

자주 조회하는 위치를 저장해 두고 지도에서 바로 고를 수 있다. **계정당 최대 10개**다.

역할을 두 화면으로 나눈다.

| 화면 | 할 수 있는 것 |
| --- | --- |
| 지도 | 저장한 장소를 눌러 조회 위치를 바로 바꾸는 것만. 여기서 추가·수정·삭제·순서 변경은 하지 않는다 |
| 저장 장소 관리 | 이름 수정, 위치·주소 수정, 순서 변경, 삭제 |

- 지도에 노출하는 순서는 관리 화면에서 정한 순서를 따른다.
- 10개에 도달하면 새로 저장하기 전에 기존 항목을 정리하도록 안내한다. 오래된 항목을 조용히 덮어쓰지 않는다.
- 저장한 장소는 사용자가 직접 만든 목록이다. 방문 이력이나 조회 이력으로 자동으로 쌓지 않는다.
- **현재 조회 기준으로 쓰고 있는 저장 장소를 삭제해도 지도의 현재 좌표는 그대로 둔다.** 그 좌표는 저장 목록에서 빠지고 일회성 지정 위치로 남는다. 삭제를 이유로 현재 위치로 되돌리거나 매장 목록을 비우지 않는다.
- 저장한 장소는 개인 데이터이므로 로그인 계정에 속한다. 비로그인 둘러보기에서는 제공하지 않는다.

## 5. WF-03 로그인·계정

- 구글·네이버·카카오 소셜 로그인.
- 같은 사람이 다른 제공자로 로그인하면 별도 계정. 이메일 일치로 자동 합치지 않는다.
- 성공하면 요청한 화면으로 복귀. 취소·실패하면 개인 기록을 새로 저장하지 않고 둘러보기로 복귀한다.
- 계정 연결은 확장.
- 계정 탈퇴는 최종 확인 후 혜택·캡처·휴지통 등 해당 계정 데이터를 삭제하며 일반 휴지통 복원을 제공하지 않는 방향으로 합의했다.
- 탈퇴는 온라인에서 처리한다. 서버 접근을 즉시 차단하고 온라인 운영 데이터·첨부는 24시간 안에 제거한다. 백업·오프라인 사본의 처리 기한은 14.3·15.4를 따른다.
- 소셜 로그인은 CupPick 혜택 데이터의 계정별 접근 관리를 대신하지 않는다. 계정이 바뀌면 다른 계정 기록·임시 작성이 노출되지 않아야 한다.

## 6. WF-04 내 혜택·브랜드 카드

### 6.1 등록 선택과 표시

1. 등록하지 않은 브랜드는 미등록으로 구분한다.
2. 상위 브랜드 카드 안에 스탬프 잔액·보유 쿠폰 수·가장 가까운 만료 정보를 요약한다.
3. 카드 선택 시 전체 내역을 보여준다.
4. 매머드는 같은 카드 안에서 두 프로그램을 구분하며 잔액을 합산하지 않는다.
5. 등록된 모든 잔액이 0이고 보유 쿠폰이 없으면 기본 혜택 목록에서 숨긴다. ‘등록한 브랜드 전체’에서 0개 기록·과거 내역을 조회·수정할 수 있고 새 혜택이 생기면 다시 표시한다. 미등록을 확인된 0개로 취급하지 않는다.
6. 만료 예상 후 미확인인 쿠폰은 보유 상태에 남으므로 자동으로 빈 브랜드로 처리하지 않는다.

### 6.2 정렬

| 모드 | 순서 |
| --- | --- |
| 만료 임박순(최초 기본값) | 브랜드 내 가장 가까운 아직 지나지 않은 만료일. 같은 날짜면 확인된 날짜 우선 |
| 선호 브랜드순 | 사용자가 지정한 브랜드 순서. 미지정 브랜드는 뒤에서 만료 임박순 |

- 마지막으로 선택한 정렬을 기억한다.
- 선호 브랜드 설정은 선택. 해당 정렬을 처음 사용할 때 브랜드·순서를 설정하고 이후 변경 가능.
- 확인된 날짜와 예상 날짜를 함께 날짜순으로 사용하되 예상 표시를 붙인다.
- 여러 스탬프 묶음은 가까운 날짜와 해당 개수 표시: ‘총 8개 · 2개가 9/20 만료 예상’.
- 지난 예상 날짜는 ‘만료 확인 필요 N건’으로 남기고 정렬에서는 다음 유효한 날짜를 사용한다.
- 다음 날짜가 없거나 날짜를 모르면 날짜 미확인 그룹에 배치한다.
- 내 혜택 카드에는 거리 표시·거리 정렬이 없다. 주변 매장 유무가 카드 노출·순서에 영향을 주지 않는다.
- 동률은 브랜드명 가나다순, 동일 이름은 고정 식별자순으로 정한다. 선호 브랜드가 없으면 만료 임박순과 동일하며 설정을 강제하지 않는다.
- 구성 확인·전환 보류 중인 스탬프 날짜는 임박 정렬에서 제외하고 ‘구성 확인 필요’로 표시한다. 같은 브랜드의 정상 쿠폰·다른 잔액은 계속 정렬에 사용한다.
- ‘지난 날짜’는 한국시간 기준 어제까지다. 오늘 만료는 오늘 하루 임박 정렬에 포함한다.

## 7. WF-05 스탬프 등록·갱신·만료 묶음

### 7.1 첫 등록

브랜드 → 정책에 따라 필요한 프로그램·용도·적립 범위 선택 → 현재 잔액 → 필요한 상세 정보 → 저장.

최초 등록은 **현재 보유 상태를 한 번에 입력**한다. 과거 적립 내역을 하나씩 다시 입력시키지 않는다.

| 브랜드 유형 | 최초 등록에서 받는 값 |
| --- | --- |
| 누적형 | 현재 스탬프 수 |
| 매장 조건형(우지커피·텐퍼센트커피) | 현재 총 스탬프 수 + 매장별 스탬프 수량 |
| 단계 교환형(매머드커피) | 매장별 스탬프 수량. 매장마다 별도 잔액으로 저장 |

매장별 수량을 받는 경우 **매장별 합계와 총 스탬프 수가 일치해야 저장한다.** 일치하지 않으면 차이를 알리고 저장을 막으며 입력은 유지한다.

잔액의 식별 단위는 **계정 + 브랜드 + 프로그램 + 용도 + 적립 범위(공통 또는 특정 지점)**다. 승급용·교환용과 지점별 잔액을 합산하지 않는다. 자동 구분은 확인된 정책만 사용한다. 범위를 모르면 임시 식별자를 가진 ‘구분 미확인’ 잔액으로 별도 저장하고 자동 교환 제안은 보류한다. 나중에 구분할 때 기존 잔액과 합산하지 않고 공식 현재 잔액으로 통합한다.

- 공통 적립에서 매장 입력을 일괄 강제하지 않는다.
- 매장 전용 또는 사용 조건에 필요한 경우 매장 정보 요청. 모르면 미확인 저장 허용.
- 매장 조건형 브랜드의 매장별 적립 수량은 만료일 묶음과 다른 축이다. 같은 스탬프를 두 축에서 이중으로 세지 않는다.
- 잔액만 아는 경우 과거 적립일·매장 내역을 모두 입력시키지 않는다.
- 묶음은 개수·만료일·필요한 경우 적립 매장으로 구분한다.
- 날짜별 묶음과 매장별 묶음이 같은 스탬프를 중복 합산하지 않도록 한다.
- 유효한 상세 수량의 합은 전체 잔액을 초과할 수 없다. 나머지는 구성 미확인 수량이다. 같은 스탬프의 날짜·매장은 하나의 묶음 속성으로 관리한다.
- 스탬프 수량은 0 이상의 정수다. 적립 추가는 양의 정수만 받는다. 음수 잔액·같은 잔액 중복 등록은 차단하고 기존 수정으로 연결한다. 서로 다른 공식 적립 계정의 동시 관리는 MVP에서 제공하지 않는다.
- 캡처는 선택이며 등록 권장 문구를 제공한다.

### 7.2 수정 방식

| 행동 | 반영 |
| --- | --- |
| 적립분 추가 | 입력 개수 추가. 적립일과 정책이 있으면 해당 묶음만 예상 만료일 계산 |
| 현재 잔액 맞추기 | 공식 앱에서 본 현재 숫자로 변경. 추가 쿠폰 생성·이중 차감 없음 |
| 현재 잔액 확인했어요 | 현재 잔액은 유지하고 공식 확인 수량을 현재 표시 수량으로 기록하며 실제 확인 시점도 갱신. 묶음 재확인·보류 해제 없음 |
| 개수는 같지만 내역이 달라요 | 잔액 유지. 영향받은 묶음의 만료 알림·자동 차감 보류 |

최초 등록 이후의 갱신은 **적립분 추가(+1 등)** 또는 **현재 수량 수정** 두 축으로 처리한다. 매장 조건형·단계 교환형처럼 매장 정보가 필요한 브랜드는 적립분을 추가할 때 적립 매장도 함께 기록하고 해당 매장의 적립 수량에 반영한다. 매장을 모르면 미확인으로 저장하되 매장별 수량에는 더하지 않는다.

공식 확인 시점, 앱에서 불러온 시점, 기록 변경 시점을 분리한다. 실제 확인 시점은 과거 확인 일시를 입력할 수 있으며 미래 일시는 허용하지 않는다. 적립분만 입력한 경우 전체 공식 잔액을 확인했다고 처리하지 않는다. 또한 화면 조회·캡처 첨부·자동 정리로 갱신하지 않는다. 오래됐다는 이유만으로 재확인을 강제하지 않는다.

### 7.3 예상 만료일

- 알려진 적립일과 확인된 적용 정책으로 해당 묶음의 예상 날짜를 계산한다.
- ‘오늘 2개 적립’은 해당 2개만 계산한다. 기존 잔액 전체에 오늘 날짜를 붙이지 않는다.
- 월과 고정 일수, 기산일 포함 여부를 구분한다.
- 계산 근거가 없거나 충돌하면 미확인으로 남긴다.
- 공식 날짜와 일치함을 사용자가 확인하면 확인된 날짜로 전환한다.

### 7.4 잔액과 상세 구성 불일치

1. 공식 현재 잔액을 먼저 저장한다. 숫자가 같아도 사용·만료·신규 적립으로 구성이 달라질 수 있다.
2. 영향받은 묶음이 확실하면 그 묶음만 보류한다. 특정할 수 없으면 **해당 잔액의 영향 가능한 기존 묶음 전체**를 보류한다. 다른 브랜드·프로그램·용도·지점의 잔액은 그대로 둔다.
3. 보류된 과거 묶음은 참고 기록이며 현재 상세 수량 합계에서 제외한다. 유지 가능한 유효 묶음만 합산하고 현재 잔액과의 차이는 구성 미확인 수량으로 둔다. 과거 묶음을 별도 수량처럼 더하지 않는다.
4. 현재 구성·수량·날짜를 확인하거나 기존 만료 정보를 버리고 날짜 미확인 수량으로 바꾸면 구성 보류를 해소할 수 있다. 상세 입력은 즉시 강제하지 않는다.
5. 확인한 현재 구성에 맞는 묶음만 활성화한다. 이미 잔액에 반영된 만료·전환 수량은 ‘현재 잔액에 반영됨’으로 연결하고 다시 차감하지 않는다.
6. 구성 보류 해소와 전환 보류 해소는 별개다. 보류 사유가 하나라도 남은 수량은 자동 처리하지 않는다.

### 7.4.1 부분 수량과 복수 보류

한 묶음 10개 중 3개만 영향받는 것이 확인되면 3개·7개의 자식 묶음으로 분리한다. 원 묶음은 분할 이력으로 남고 활성 합계에서 제외한다. 자식은 날짜·근거·원래 계보를 승계하며 분할 자체는 잔액을 바꾸지 않는다. 기존 차감 배분은 원 사건을 유지하고 현재 남은 수량만 분할한다.

전환 보류 3개는 현재 구성에 포함될 수 있지만 자동 차감·알림은 중지한다. 구성 자체가 불명확한 3개는 보류 과거로 전환되어 현재 상세 합계에서 제외된다. 한 자식에 여러 보류 사유가 있어도 수량은 한 번만 계산한다. 부분 중첩이면 겹치는 구간까지 다시 분할한다. 특정 불가면 영향 가능한 기존 묶음 전체를 보류하며 새 적립분에 자동 확산하지 않는다.

### 7.5 만료 정리

| 날짜 상태 | 처리 |
| --- | --- |
| 확인된 날짜·유효한 구성·처리 보류 없음 | 만료 시 해당 묶음을 잔액에서 자동 차감하고 만료 내역으로 이동 |
| 예상 날짜 | 만료 예상 개수 표시. 사용자 확인 후 차감 |
| 미확인 또는 구성 불일치 | 자동 차감하지 않음 |

수동 차감·잔액 수정은 실제 기록상 잔액에 반영하고 변경 내역을 남긴다. 별도 자동 정리 알림은 보내지 않는다. 자동 차감은 잔액 반영·내역·안내를 함께 제공한다. 자동 정리는 영구 삭제가 아니다.

자동 정리 결과에는 **‘등록한 만료 정보 기준’**을 표시한다. 수동 기록에 알리지 않은 변동은 탐지할 수 없으며 자동 정리로 공식 확인 시점을 갱신하지 않는다.

잘못된 자동 차감의 복구는 수정한 날짜·원래 묶음·차감 사건을 함께 평가한다. 이후 수정 없이 정확한 수량을 재구성할 수 있으며, 날짜가 아직 유효한 것으로 확인됐거나 기간 제한 없음이 확인된 경우에만 복구 개수·최종 잔액을 미리 보여주고 한 번만 더한다. 여전히 확인된 만료일이 지났다면 만료 내역으로만 복구한다. 예상 날짜이거나 이후 수정으로 반영 여부가 불명확하면 **공식 현재 잔액을 입력받아 맞추고 수량을 추측해 더하지 않는다.** 확인되지 않은 옛 묶음은 보류한다.

예상 날짜가 지난 스탬프는 날짜가 지났다는 사실만으로 차감하지 않는다. ‘공식 앱에서 만료를 확인했어요’에서 현재 잔액에 이미 반영됐는지를 확인한다. 미반영 수량·묶음이 특정되면 한 번 차감하고, 이미 반영됐거나 구성을 모르면 공식 현재 잔액으로 맞춘다. 보류 사유가 남으면 해제하지 않는다.

정리 작업은 실행 시 최신 잔액·구성·보류 상태를 다시 확인한다. 처리 중 수동 수정이 먼저 저장되면 다시 평가한다. 수량 부족·구성 충돌이면 음수로 차감하거나 일부를 임의 차감하지 않고 해당 묶음을 보류한다. 날짜가 과거인 기록을 새로 저장할 때는 9.2의 날짜 처리 및 저장 전 미리보기를 적용한다.

## 8. WF-06 쿠폰 전환·복수 발급·취소

### 8.1 전환 기록

1. 적립분 추가로 확인된 기준에 도달하면 공식 앱 발급 확인을 안내한다.
2. 실제 발급 또는 선택 교환을 확인한 뒤 쿠폰 기록과 필요한 잔액 조정을 함께 저장한다.
3. 자동 발급과 선택 교환, 여러 교환 기준을 수용한다. 모든 브랜드를 10개 자동 발급으로 취급하지 않으며 하나의 `교환하기` 동작으로 통일하지 않는다.

| 브랜드 유형 | 기준 도달 안내 | 사용자 행동 | CupPick 처리 |
| --- | --- | --- | --- |
| 자동 발급형(누적형·매장 조건형) | `쿠폰이 발급될 시점이에요` | 공식 앱에서 실제 쿠폰 확인 → `발급된 쿠폰 기록하기` | 쿠폰 기록 + 미반영 차감 |
| 선택 교환형(매머드커피) | `아메리카노 쿠폰으로 교환할 수 있어요`(12개) / `모든 음료 쿠폰으로 교환할 수 있어요`(20개) | 공식 앱에서 교환 → `공식 앱에서 교환했어요`. 교환하지 않고 `계속 모으기` 가능 | 선택한 단계의 쿠폰 기록 + 해당 단계 수량 차감 |

어느 경우에도 CupPick이 공식 쿠폰을 발급하지 않는다. 기준에 도달했다는 사실만으로 쿠폰을 만들거나 스탬프를 차감하지 않는다.

4. 발급 여부를 모르면 쿠폰을 만들지 않고 추가 차감하지 않는다. 기록한 잔액은 유지하며 ‘전환 확인 필요’ 표시.
5. 이미 차감된 현재 잔액을 등록했다면 같은 전환으로 다시 차감하지 않는다.
6. 쿠폰에 사용된 스탬프 묶음과 이후 남거나 새로 적립한 스탬프는 분리한다.
7. 전환됐을 가능성이 있는 수량은 자동 만료 차감을 보류한다. 대상을 모르면 해당 잔액의 영향 가능한 묶음 전체를 보류한다. 잘못된 임박 안내를 피하기 위해 이 묶음의 만료 알림도 보류한다.
8. 발급 확인 후 아직 반영하지 않은 전환 차감만 한 번 적용한다. 현재 잔액 맞추기로 이미 반영한 경우에는 연결 기록만 남기고 추가 차감하지 않는다. 발급되지 않았음을 확인하면 보류를 해제하고 유효한 구성·날짜를 재평가한다. 실제 전환일·당시 수량을 재구성할 수 없으면 공식 현재 잔액으로 맞춘다. 전환과 만료를 같은 수량에 이중 적용하지 않는다.

### 8.2 차감할 묶음

공식 차감 순서를 확인했다면 그 규칙을 적용한다. 미확인이면 알려진 만료일 가까운 묶음부터 제안하되 예상 표시·날짜 미확인 수량을 함께 보여준다. 동률은 오래된 적립일, 그다음 고정 식별자순이다. 이는 입력 보조이며 사용자 확인 전 적용하지 않는다. 확인할 수 없으면 공식 현재 잔액과 쿠폰을 저장하고 7.4에 따라 영향 가능한 묶음의 알림·자동 차감을 보류한다. 차감 규칙·현재 잔액을 둘 다 모르면 쿠폰만 독립 기록하고 스탬프는 전환 확인 필요로 유지한다.

사용 가능 매장 목록이 공식 쿠폰에 있다면 그 목록을 우선 등록한다. 쿠폰 사용 조건을 위해 과거 적립 내역 전체를 재입력시키지 않는다.

매장 조건형 브랜드는 쿠폰을 기록하는 시점의 **매장별 적립 수량을 그 쿠폰에 스냅샷으로 고정**한다. 이후 새로 적립한 스탬프로 기존 쿠폰의 사용 가능 매장을 다시 계산하지 않는다. 기록 후의 적립은 다음 쿠폰을 위한 별도 상태로 쌓는다. 자세한 규칙은 10.1을 따른다.

### 8.2.1 독립 등록 쿠폰에 전환 연결

전환 확인에서 새 쿠폰 등록 또는 기존 쿠폰 선택을 제공한다. 기존 쿠폰 선택은 이름·브랜드만으로 자동 확정하지 않고 사용자가 같은 실제 쿠폰임을 확인한다. 같은 계정·브랜드이고 알려진 프로그램이 일치해야 한다. 프로그램 미확인은 전환 대상 프로그램을 확인한 뒤 연결한다.

기존 쿠폰 ID·날짜·조건·첨부·사용/만료 상태는 유지한다. 보유뿐 아니라 사용 완료·만료 쿠폰도 전환 이력 연결은 가능하다. 휴지통은 복원 후 연결하며 전환 취소 쿠폰은 재연결하지 않는다. 이미 동일 전환에 연결됐다면 기존 결과를 반환하고 다른 전환에 연결됐다면 차단한다.

차감이 이미 현재 잔액에 반영됐는지 선택하고 그 근거가 되는 잔액 확인 사건에 연결한다. 미반영 수량이 정확한 경우만 차감하며, 모르면 공식 현재 잔액으로 맞춘다. 연결만으로 쿠폰 수·공식 사용 상태가 바뀌거나 알림이 새로 생기지 않는다. 연결된 보류 사유만 해소한다.

### 8.3 복수 쿠폰

여러 장은 공통 정보를 한 번 입력하고 개별 값을 수정할 수 있게 한다. 각 쿠폰은 별도 기록으로 저장하여 사용·삭제·만료를 독립 관리한다. 실제 확인한 발급 수량만 처리한다.

### 8.4 실패·취소

- 쿠폰 등록과 연결된 스탬프 차감은 함께 성공하거나 모두 미반영.
- 반복 클릭·재시도로 같은 기록이 중복 생성·차감되지 않음.
- 잘못된 전환 기록은 ‘전환 취소’로 쿠폰 등록과 연결된 차감을 함께 되돌림.
- 이후 잔액 수정·쿠폰 사용 등 영향이 있으면 복구 결과를 먼저 확인받음.
- 일반 쿠폰 삭제와 전환 취소는 다른 행동. 쿠폰 삭제만으로 스탬프를 되돌리지 않음.
- 공식 앱의 쿠폰 발급을 취소하는 기능이 아님.
- 복수 전환 중 한 장만 취소할 수 있다. 각 쿠폰에 연결된 차감 사건·수량·묶음을 사용한다. 공통 차감을 분리할 수 없으면 공식 현재 잔액으로 맞춘다.
- 취소 대상 쿠폰은 전환 취소 이력으로 남기고 보유·알림에서 제외한다. 이미 사용 완료된 쿠폰은 사용 기록도 잘못됐는지 함께 확인하며, 실제 사용한 쿠폰의 전환을 취소해 스탬프를 더하지 않는다.
- 원래 날짜가 확인됐고 지났으면 만료 내역으로 복구하고 활성 잔액에 더하지 않는다. 기간 제한 없음이 확인된 수량은 구성·반영 이력이 정확할 때만 활성 잔액으로 복구한다. 예상 날짜·구성 불명확이면 7.5의 공식 잔액 맞추기를 적용한다. 다른 보류 사유가 남으면 해제하지 않는다.
- 원래 잔액이 삭제됐거나 원장 근거가 없으면 자동 복구하지 않는다. 필요하면 스탬프를 다시 등록하면서 공식 현재 잔액으로 맞춘다.

## 9. WF-07 쿠폰 등록·날짜·중복·캡처

### 9.1 최소 입력

- 현재는 쿠폰 하나의 단일 사용 상태를 관리한다. 금액권 부분 사용·충전 잔액 및 기프티콘 전용 연동은 00의 후순위이며 임의 구현하지 않는다.
- 전환 등록은 ‘스탬프 쿠폰’ 자동 지정.
- 직접 등록은 ‘스탬프 / 행사·기타 / 모름’ 선택. 대상 브랜드·구분 가능한 쿠폰 이름 또는 혜택 설명은 필수이고, 날짜·사용 매장·프로그램 상세는 모르면 미확인으로 둔다. 이 입력은 보유 쿠폰 관리이며 브랜드 행사 수집 기능이 아니다.
- 브랜드·필요한 프로그램·혜택을 기록하고 개인별 조건을 입력.
- 발급일을 알면 선택하거나 ‘오늘 발급받았어요’를 사용.
- 해당 종류의 확인된 정책이 있으면 예상 만료일 표시 후 저장 한 번으로 완료. 별도 계산 확인 단계는 강제하지 않음.
- 공식 앱 날짜를 확인한 경우만 ‘날짜 확인했어요’로 확인된 날짜로 저장. 실제 만료일 직접 입력·수정 가능.
- 등록일을 발급일로 간주하지 않음.
- 행사·기타·모름에 일반 스탬프 쿠폰 기간을 임의 적용하지 않음.
- 근거가 부족하면 만료일 미확인 저장. 날짜를 모른다고 등록을 막지 않음.

### 9.2 기간과 시작 조건

- 만료일은 한국시간 날짜 기준, 해당 날짜 다음 날 00:00부터 만료로 처리한다.
- 확인된 만료일의 쿠폰은 휴지통이 아닌 보유 상태일 때만 만료 내역으로 이동한다. 자동 날짜 처리로 사용 완료·전환 취소·휴지통 상태를 덮어쓰지 않는다.
- 예상 만료일 경과 시 자동 만료하지 않고 ‘만료 여부 확인 필요’ 표시. 사용했어요/만료됐어요/날짜 수정 제공.
- 발급일(`issuedAt`)과 사용 시작 시점(`usableFrom`)은 별도 값이다. 브랜드에 따라 발급 직후 바로 쓸 수 없는 경우가 있으므로 같은 값으로 취급하지 않는다.
- 사용 시작 날짜가 확인되면 ‘내일부터 사용 가능’ 또는 날짜 표시. 빽다방 스탬프 쿠폰은 발급 다음 날부터 사용할 수 있다.
- 발급 후 일정 시간 대기가 필요한 브랜드는 `usableFrom`을 분 단위로 계산해 ‘N분 후 사용 가능’으로 표시한다. **메가MGC커피 스탬프 리워드 쿠폰은 발급 직후 5분간 사용할 수 없고 5분이 지나면 사용할 수 있다.** 즉 `usableFrom = issuedAt + 5분`이며 두 값을 따로 저장한다. 발급 사실 자체는 `issuedAt` 시점에 기록하고, 그 5분 동안 표시 상태는 `아직 사용 불가`다.
- 브랜드별 대기 시간은 확인된 정책이 있을 때만 값으로 사용하고, 없으면 조건 문구로만 안내한다. 사용자에게 시·분 입력을 강제하지 않는다.
- 매장 영업시간·메뉴·사용 조건을 확인하도록 안내. 날짜 표시는 실제 영업 마감을 보장하지 않음.
- 정확한 사용 시각을 입력·계산하는 고도화는 확장. 특정 시각 제한을 알고 있다면 조건 문구로 명시하고 날짜만으로 사용 가능을 단정하지 않는다.
- 확인된 날짜가 지난 쿠폰을 등록하면 저장 전 ‘만료 내역에 저장’ 안내 후 저장한다. 과거 만료 스탬프가 현재 잔액에 포함됐는지 모르면 자동 차감하지 않고 공식 현재 잔액으로 맞춘다. 날짜 수정으로 즉시 만료·차감될 경우에도 결과를 먼저 보여준다.
- 날짜 자체가 없음을 공식 확인한 ‘기간 제한 없음’은 날짜 미확인과 구분한다. 만료 알림·자동 정리 대상에서 제외하며 날짜 없는 정렬 그룹에 둔다.
- 시작일이 만료일보다 늦으면 날짜 오류를 안내한다. 확인된 상충 값을 그대로 저장하지 않으며, 모르는 조건은 미확인으로 저장할 수 있다.
- 일수·달수·월말·윤년·기산일 포함 기준을 확인하지 못하면 계산하지 않는다. 정책을 검증한 경우에만 그 규칙으로 예상 날짜를 계산한다.

### 9.3 중복 의심

같은 브랜드·혜택·만료일의 기존 쿠폰을 보여주고 기존 유지/별도 추가를 선택한다. 실제 복수 보유가 가능하므로 강제 차단하지 않는다. 만료일 미확인만으로 모두 같은 쿠폰이라고 판단하지 않는다. 휴지통에 같은 기록이 있으면 복원과 별도 추가를 구분한다.

### 9.4 캡처

첨부·조회·교체·삭제는 선택. ‘화면을 함께 남기면 나중에 기록을 확인하기 쉬워요’ 안내를 제공한다. 캡처 추가가 날짜·조건·잔액 확인을 대신하지 않고 알림도 바꾸지 않는다. 실제 사용은 공식 앱 등 브랜드가 인정하는 수단을 이용한다. 한도·수명은 14.3을 따른다. 첨부 업로드가 실패하면 입력을 유지하고 재시도 또는 ‘첨부 없이 저장’을 제공하며 첨부가 저장됐다고 표시하지 않는다.

## 10. WF-08 사용 매장 조건

### 10.1 조건 관리

적립 범위와 쿠폰 사용 범위, 적립 제외와 쿠폰 사용 제외는 각각 관리한다. 현재 잔액·단골·매장 이름만으로 가능 여부를 추정하지 않는다.

### 10.1.1 매장 조건형 브랜드의 사용 가능 매장

우지커피·텐퍼센트커피는 **해당 매장에서 3개 이상 적립한 경우 그 매장에서 쿠폰을 사용할 수 있다.** 판정에 매장별 적립 수량이 필요하므로 다음을 지킨다.

1. 스탬프 등록·갱신 시 적립 매장을 받고 매장별 적립 수량을 관리한다.
2. 쿠폰을 기록하는 시점의 매장별 적립 수량을 그 쿠폰의 **사용 가능 매장 상태로 보존**한다. 매장 이름과 당시 적립 수량을 함께 남긴다.
3. **기존 쿠폰의 사용 가능 매장을 이후에 새로 적립한 스탬프로 다시 계산하지 않는다.** 보존한 상태만으로 그 쿠폰을 판정한다.
4. 기록 후의 적립은 다음 쿠폰을 위한 상태로 따로 쌓는다. 기존 쿠폰의 보존 상태와 섞지 않는다.
5. 보존 상태에 없는 매장은 불가가 아니라 미확인이다. 3개 미만으로 보존된 매장은 그 쿠폰에 대해 사용 불가로 표시하고 부족한 수량을 함께 보여준다.

이 규칙은 서비스가 확인한 공통 정책이 근거다. 사용자가 자기 쿠폰에서 직접 확인한 매장 근거는 10.1의 개인 확인 경로로 따로 관리한다.

| 등록 경로 | 판정 |
| --- | --- |
| 확인된 브랜드 공통 조건 적용 | 해당 쿠폰 종류·프로그램에 적용되는 공통 정책과 확인된 예외 반영 |
| 지정 매장 목록 등록 | 사용자가 자기 쿠폰에서 확인한 매장은 가능. 일부 목록이면 목록 밖은 미확인 |
| 전체 목록 확인 | ‘사용 가능한 매장을 모두 등록했어요’ 확인 시에만 목록 밖을 불가로 표시 |
| 사용 범위 미확인 | 미확인 저장. 등록 차단·전체 불가 처리 없음 |

‘전국 사용·일부 매장 제외’이면 모든 매장을 입력시키지 않는다. 확인된 제외점은 불가, 개별 확인점은 가능으로 표시한다. 예외 목록의 완전성을 모르면 나머지는 미확인이다. 제외 없는 전국 사용을 확인했거나 완전한 예외 목록의 적용을 확인한 경우에만 나머지를 가능으로 표시한다.

근거는 **서비스 확인 공식 정책 / 사용자가 해당 쿠폰·공식 화면에서 확인 / 근거 미확인**으로 구분하며 확인일·적용 대상을 함께 보관한다. 개인 조건은 그 개인 기록에만 적용하고 공통 정책으로 확대하지 않는다. 캡처 첨부는 선택이며 첨부만으로 확인 상태를 올리지 않는다.

개인 조건과 공통 정책이 충돌하면 적용 대상·시점부터 비교한다. 개별 예외임이 확인된 경우 그 예외를 적용한다. 해소되지 않으면 해당 쿠폰·매장 조건만 ‘미확인 · 조건 확인 필요’로 내려 근거를 함께 보여준다. 다른 조건·잔액·날짜는 유지한다. 공항·휴게소 등 명칭만으로 불가 판정하거나 기프티콘 예외를 스탬프 쿠폰에 옮기지 않는다.

### 10.2 매장 연결 실패·폐점

검색되지 않으면 매장명 직접 입력 후 ‘지도 매장 연결 전’ 저장. 연결 전에는 특정 지도 매장에서 쓸 수 있다고 표시하지 않는다. 나중에 연결해도 기록 유지.

폐점 확인은 ‘폐점 매장’, 검색 누락·정보 불충분은 ‘매장 정보 확인 필요’. 스탬프·쿠폰을 자동 삭제하거나 소멸했다고 판단하지 않는다. 타 매장 사용 가능성은 별도 확인한다.

## 11. WF-09 지도에서 혜택 비교

### 11.1 화면 역할

- 내 혜택: 잔액·쿠폰·만료·사용 조건 중심. 거리 없음.
- 지도·매장 상세: 조회 위치 기준 도보 거리·예상 시간, 해당 매장과 관련된 내 혜택, 외부 길찾기.
- 카페 선택은 사용자가 한다. 추천 점수·추천 순위 없음.

### 11.2 혜택별 지도 연결

| 선택 항목 | 버튼 | 매장 표시 상태 |
| --- | --- | --- |
| 스탬프 잔액 | 주변 적립 매장 보기 | 적립 가능으로 확인 / 적립 여부 미확인 / 적립 불가로 확인 |
| 보유 쿠폰 | 주변 사용 매장 보기 | 사용 가능으로 확인 / 사용 여부 미확인 / 사용 불가로 확인 |

1. 선택 브랜드·프로그램의 매장을 조회 위치 기준으로 표시한다. 미확인·불가 매장도 상태를 구분해 표시하며 없었던 혜택을 만들지 않는다.
2. 지도 상단에 기준 브랜드·프로그램·선택 혜택·만료 정보를 표시한다. 스탬프는 용도·적립 범위를 구분한다.
3. 기준 혜택을 바꾸면 조건을 다시 계산한다. 만료일·시작일·메뉴·주문 조건은 별도 표시한다.
4. 스탬프 8개를 쿠폰 보유로 표시하지 않는다. 쿠폰 전환 조건과 적립 가능 조건도 구분한다.
5. 범위 내 매장 없음과 조회 실패를 구분한다. 범위 밖 지정 매장은 목록에서 직접 열 수 있고, 내 혜택의 노출·정렬은 바꾸지 않는다.
6. 기록이 다른 기기에서 삭제·사용 완료·만료된 경우 진입 시 최신 상태를 보여주고 활성 혜택 기준 지도 연결을 해제한다. 매장 일반 탐색은 계속 허용한다.

### 11.3 지도 목록 정렬

도보 예상 시간 오름차순, 동률은 도보 거리·매장명·고정 식별자순이다. 도보 정보 없는 후보는 ‘도보 정보 미확인’ 그룹으로 뒤에 표시한다. 사용 가능 여부로 정렬을 조용히 바꾸지 않는다. 조회된 후보 간 정렬이며 아직 불러오지 않은 모든 매장까지 전국 최단순이라고 표현하지 않는다.

## 12. WF-10 만료 알림·자동 정리 안내

### 12.1 대상과 시각

- 확인된 날짜와 예상 날짜가 있는 쿠폰·유효한 스탬프 묶음의 D-3·당일 한국시간 오전 8시.
- 예상 날짜 알림은 예상 기준임을 명시.
- 만료 예정 알림은 휴지통이 아닌 보유 쿠폰과 처리 보류 없는 유효 스탬프만 대상이다. 기간 제한 없음·날짜 미확인·구성/전환/정책 보류·사용 완료·만료·전환 취소·휴지통은 예정 알림에서 제외한다. 자동 정리 결과 안내는 이 예정 대상과 별도로 수집한다. 대상과 결과가 모두 없으면 빈 요약 푸시를 보내지 않는다.
- 같은 날 만료 예정과 전날 이후 자동 정리 결과를 **계정당 하나의 오전 8시 요약**으로 묶고 안에서 구분한다. 단일 대상은 상세, 여러 대상은 목록으로 연결한다.
- 자동 정리는 만료 시점에 반영하고 결과 안내는 오전 8시에 묶는다. 수동 차감은 잔액·내역을 반영하되 별도 자동 정리 알림을 보내지 않음.
- 알림을 꺼도 앱 이용·자동 정리는 유지하고 결과는 앱 안에서 확인 가능.
- 알림 설정을 이용하려 할 때 권한 안내. 반복 강제하지 않음.

### 12.2 재예약

등록·수정·복원 후 미래에 남은 일정만 예약한다. 이미 지난 알림을 몰아서 보내지 않는다. 날짜 수정만으로 같은 날 같은 쿠폰 알림을 반복하지 않는다. 기간 제한 없음·미확인 날짜로 바꾸면 미래 만료 알림을 모두 취소한다. 사용 완료·삭제 시 예약 취소. 캡처 변경은 알림 일정에 영향 없음.

오전 8시 이후 완료한 자동 정리 결과는 다음 날 요약에 포함한다. 장애로 지난 만료 예정 알림은 소급하지 않으며 앱 안의 상태는 최신으로 갱신한다. 알림은 조회·사용·삭제 상태를 발송 직전에 다시 확인한다.

푸시는 ‘이 기기에서 알림 받기’를 켠 로그인 기기 모두에 같은 일일 요약의 기기별 발송 항목을 하나씩 생성한다. 실제 수신 횟수는 외부 전달 상태에 따라 달라질 수 있으며 결과 불명 처리 기준은 05 POL17을 따른다. 앱 내 요약은 계정에 하나이며 같은 계정의 확인 상태를 동기화한다. 계정·한국 날짜·기기별로 중복 방지하고 결과 불명 재시도를 새 알림으로 만들지 않는다. 로그아웃·탈퇴 기기는 발송 대상에서 즉시 제외한다. 권한 거부 기기는 앱 내 요약만 제공한다. 운영체제 전달 지연 가능성 때문에 오전 8시 수신 자체를 보장하지 않는다.

## 13. WF-11 사용 완료·되돌리기

1차 구현에서는 공식 앱과 자동으로 연동하지 않는다. 사용자가 실제 공식 앱·매장에서 사용한 뒤 CupPick 기록을 **직접 사용 완료로 변경**한다. 사용 완료 내역은 보유 혜택·만료 알림에서 제외한다.

되돌리면 날짜 상태를 다시 평가한다. 확인된 날짜가 지났으면 만료, 예상 날짜가 지났으면 확인 필요, 미확인은 미확인 상태의 보유 기록으로, 확인된 기간 제한 없음은 무기한 보유 상태로 복귀한다. 되돌리기를 실제 쿠폰 재발급으로 표현하지 않는다.

잘못된 만료일을 수정한 만료 쿠폰도 같은 날짜 재평가를 적용한다. 사용 완료 기록은 날짜를 고쳐도 보유로 자동 복귀하지 않으며 별도의 사용 취소가 필요하다. 휴지통 기록은 날짜를 고쳐도 복원 전까지 활성화하지 않는다.

## 14. WF-12 삭제·휴지통·복원

### 14.1 삭제 대상별 영향

| 행동 | 현재 잔액·쿠폰 영향 | 복원 |
| --- | --- | --- |
| 과거 적립·차감 내역 삭제 | 현재 잔액 유지. 기록 목록에서 제거 | 기록만 복원, 수량 재가감 없음 |
| 만료 정보 삭제 | 해당 수량 유지, 날짜만 미확인. 관련 알림·자동 차감 해제 | 현재 묶음과 충돌 없을 때 정보만 복원. 수량 추가 없음 |
| 스탬프 등록 삭제 | 해당 잔액·연결 묶음 함께 휴지통. 다른 잔액·발급 쿠폰 유지 | 공식 현재 잔액과 현재 구성을 확인해 복원 |
| 쿠폰 삭제 | 보유·알림에서 제외. 전환 스탬프를 되돌리지 않음 | 날짜·이전 사용 상태를 재평가해 복원 |
| 캡처 삭제·교체 | 잔액·쿠폰·확인일·알림 유지. 교체 전 파일은 휴지통 | 대상에 다시 첨부, 장수 한도 적용 |

내역 삭제는 잔액 수정이나 전환 취소가 아니다. 삭제 전 대상·개수·영향·복원 기한을 보여준다. 삭제된 대상의 알림은 취소한다. 기록 복원은 공식 혜택 복원으로 표현하지 않는다.

### 14.2 휴지통·충돌·복원

- 사용자 삭제 항목은 기본적으로 삭제 시각부터 60×24시간 보관 후 영구 삭제한다. 휴지통 사진을 사용자가 선택 영구 삭제한 경우는 14.2.1을 따른다. 기한은 한국시간으로 표시한다. 복원은 만료 시각 전까지만 가능하다.
- 휴지통은 활성 혜택·알림·잔액 합계에서 제외한다. 만료·사용 완료 내역과 구분한다.
- 같은 잔액을 새로 등록했다면 현재 5개와 과거 8개를 13개로 합치지 않는다. 두 기록을 비교하고 **공식 현재 잔액을 기준으로 하나의 활성 잔액**으로 정리한다. 예전 묶음은 현재 구성 확인 전 활성화하지 않는다.
- 새 등록이 없어도 삭제 기간 동안 실제 잔액이 달라질 수 있다. 현재 잔액을 확인하지 못하면 복원을 보류하고 휴지통에 유지한다. 취소해도 삭제 기한을 연장하지 않는다.
- 만료 정보 복원 중 대상 수량이 이미 사용·차감·변경됐으면 덮어쓰지 않는다. 현재 구성을 확인하거나 날짜 미확인을 유지한다. 확인된 과거 만료 정보가 현재 잔액에 이미 반영됐다면 재차감하지 않는다.
- 연결 첨부는 부모 기록과 함께 이동·복원한다. 부모보다 먼저 독립 삭제한 첨부는 부모 복원으로 살아나지 않는다. 부모 삭제 기한이 끝나면 종속 첨부도 제거한다.
- 원본 대상이 영구 삭제된 첨부는 복원하지 않는다. 복원 시 미래 알림만 생성한다. 복원한 일반 이력의 365일 보관 기한이 이미 지났다면 복원 시각부터 30일 조회 유예를 제공하고 다시 정리한다. 보유 혜택으로 정상 복원된 기록에는 활성 보관 규칙을 적용한다.

### 14.2.1 첨부 복원·용량 확보

사진 복원 후에도 기록당 활성 3장 이하여야 한다. 자리가 부족하면 복원 가능한 수를 표시하고 복원할 사진을 선택하게 한다. 선택하지 않은 사진은 원 삭제 기한으로 유지한다. 부모 복원은 사진을 0~3장 선택해 함께 복원할 수 있으며, 미선택 사진은 기존 삭제 기한을 유지하는 독립 휴지통 항목으로 전환한다. 사진의 자리 부족이 부모 기록 복원을 막지 않는다.

계정 300MB에는 휴지통도 포함하므로 일반 삭제·교체만으로 공간이 늘지 않음을 안내한다. 용량 화면에서 휴지통 사진을 선택해 영구 삭제할 수 있다. 대상·확보 예상 용량·복원 불가를 보여주고 최종 확인 후 처리한다. 활성 사진은 먼저 일반 삭제해야 하며 기록 전체 일괄 영구 삭제 기능으로 확대하지 않는다. 실패 시 용량이 확보됐다고 표시하지 않고 실제 객체 삭제 성공 후 한도를 반환한다. 백업 사본은 최대 30일 정책을 따르고 복원 차단을 적용한다.

| 사용·만료·변경 일반 이력 | 사건 발생 후 365일. 30일 전 앱 내 안내 후 자동 정리. 첨부도 함께 정리하며 추가 60일 휴지통은 적용하지 않음 |

| 복구·중복 방지용 최소 연결 기록 | 관련 활성 혜택·휴지통·보류 처리와의 연결이 끝날 때까지 수량·사건 식별자 등 최소 정보만 보관. 삭제한 설명·이미지는 보관하지 않음 |
| 서버 백업 | 최대 30일 순환 보관. 삭제된 자료를 운영 데이터로 다시 노출하지 않도록 삭제 목록 재적용 |

365일이 지나 자동 정리된 일반 내역은 조회·사건 취소를 제공하지 않는다. 현재 잔액 맞추기는 언제든 가능하며 최소 연결 기록은 중복 처리 방지에만 사용한다.

탈퇴 시 휴지통 복원은 제공하지 않는다. 온라인 운영 데이터는 24시간 안에 삭제하며 백업은 최대 30일 안에 순환 제거한다. 사용자가 외부로 따로 저장한 원본 캡처는 CupPick 삭제 대상이 아니다.

## 15. WF-13 저장·오프라인·임시 작성·충돌

### 15.1 저장 안정성

전환 쿠폰과 차감은 함께 성공하거나 모두 미반영. 반복 요청도 한 번만 반영. 저장 결과가 불명확하면 완료로 표시하지 않고 기존 처리 결과를 확인해 재시도한다. 실패 시 작성 내용 유지.

다른 기기에서 먼저 저장된 변경을 오래된 화면으로 덮어쓰지 않는다. 최신 기록과 작성 내용을 비교하여 다시 수정하도록 안내한다.

### 15.2 오프라인

- 기기에 남은 마지막 혜택 기록 조회 가능.
- ‘오프라인 · 마지막으로 불러온 기록’과 불러온 시점 표시.
- 등록·수정·사용 처리의 확정 저장은 온라인에서 수행.
- 연결이 끊겨도 입력 유지. 재연결 저장 전 최신 기록과 충돌 확인.
- 저장된 기록이 없으면 연결 안내.
- 자동 정리가 진행됐더라도 오프라인 사본을 최신 잔액으로 표시하지 않는다.

### 15.3 임시 작성

- 등록·수정 중 나가도 작성 내용 임시 보관, 다시 이어 쓰기 가능.
- 확정 저장 전에는 잔액·쿠폰·알림에 미반영.
- 작성 기기에 계정별 보관, 같은 계정만 접근. 다른 기기에는 저장 완료 기록만 공유.
- 로그아웃 시 기본 유지. ‘이 기기의 임시 작성 내용도 삭제’ 선택 가능.
- 이어 쓰기 저장 시 최신 기록과 비교. 변경이 있으면 작성 내용과 함께 보여줌.
- ‘작성 내용 버리기’ 제공.
- 초안은 기기·계정당 20건, 마지막 편집 후 30일 보관한다. 만료 7일 전부터 앱에서 안내한다. 한도 도달 시 기존 초안 이어 쓰기·삭제를 안내하며 조용히 오래된 초안을 덮어쓰지 않는다.
- 신규 작성은 작업당 하나, 기존 기록 수정은 대상당 하나의 초안을 유지한다. 저장 성공 시 해당 초안을 지운다. 로그인 실패·저장 실패 시 유지한다.
- 초안 첨부도 기록당 3장·장당 10MB 한도이며 기기·계정당 초안 첨부 100MB까지다. 온라인 확정 저장 시 계정 첨부 한도를 다시 확인한다.
- 대상이 휴지통이면 먼저 복원해야 기존 수정 저장이 가능하다. 영구 삭제됐으면 기존 대상에 저장할 수 없으며, 새 기록으로 등록할 때 중복 검사를 다시 수행한다.
- 대상이 사용 완료·만료·전환 상태로 바뀌었으면 최신 상태를 보여주고 허용된 수정만 다시 적용한다. 초안 저장으로 상태를 자동 되돌리지 않는다.

### 15.4 계정별 사본·탈퇴 후 기기 처리

- 로그아웃하면 개인 조회 사본과 인증 정보를 지운다. 초안은 기존 합의대로 기본 유지하되 같은 계정의 재인증 전 접근을 차단한다. 선택한 경우 초안도 삭제한다.
- 오프라인 조회는 마지막 온라인 인증 후 최대 7일, 동일 로그인 계정의 기기에서만 허용한다. 초안 보관 기간과 조회 권한 기간은 별개다.
- 탈퇴한 현재 기기의 사본·초안은 즉시 삭제한다. 다른 기기는 다음 연결 시 탈퇴 상태를 확인해 삭제한다. 연결되지 않은 기기를 원격 즉시 삭제했다고 표현하지 않는다.
- 오프라인 7일이 지나면 개인 기록 조회를 차단하고 재인증을 요구한다. 탈퇴 계정은 재인증에 실패하며 로컬 데이터를 제거한다. 장기 오프라인 초안도 30일 보관 기한을 적용한다.
- 조회 사본·초안은 계정별 보호 저장소를 사용하고 일반 기기 백업에서 제외한다. 재설치·기기 분실 후 초안 복구를 보장하지 않는다.

## 16. 데이터·정책 일관성

1. 계정/브랜드/프로그램/용도/적립 범위와 쿠폰 종류를 구분한다. 범위 미확인 기록은 자동 합산하지 않는다.
2. 잔액·묶음·전환 쿠폰·정리 내역의 관계를 보존하여 이중 차감·복구를 막는다.
3. 확인된 날짜·예상 날짜·미확인·확인된 기간 제한 없음과 구성 확인 상태는 별도로 저장한다.
4. 계산한 정책 버전·근거·기산일을 남긴다.
5. 정책 변경으로 기존 잔액·쿠폰 날짜·사용 매장을 임의 수정하지 않는다.
6. 새 정책은 적용 대상·시점이 확인된 범위에 반영하며 기존 혜택 영향은 사용자 확인 후 갱신한다.
7. 충돌하거나 미확인인 규칙을 새 자동 판단에 사용하지 않는다.
8. 정책 상태와 사용자가 실제 확인한 개인 기록의 상태를 혼동하지 않는다.
9. 자동 정리·서버 동기화는 공식 잔액을 확인한 시점을 갱신하지 않는다.
10. 만료 이동, 사용 완료, 삭제, 전환 취소는 서로 다른 사건으로 관리한다. 사건 실행 순서·처리 식별자로 차감과 복구를 각각 한 번만 적용한다.

### 16.1 정책·매장 데이터 운영

- 운영 담당자 1명 이상을 출시 전에 지정한다. 공식 원문 URL·확인일·시행일·대상·계산 기준·예외·버전을 검토하고 자동 기능 적용 전 테스트 사례를 기록한다. 소비자용 운영자 화면을 별도 개발하는 것은 MVP에 포함하지 않는다.
- 정책은 파일럿 전 전수 확인하고 이후 월 1회 및 공식 변경 공지 확인 시 재검토한다. 90일간 재확인되지 않은 공통 정책은 신규 계산·공통 매장 판정에서 보류한다. 개인이 직접 확인한 날짜·조건을 이 이유만으로 삭제하지 않는다.
- 오류가 확인되면 영향을 받는 규칙의 신규 계산·판정과 의존 자동 정리를 즉시 중지한다. 기존 개인 기록을 조용히 고치지 않으며 사용자에게 영향·현재 잔액 확인을 안내한다. 근거가 별개인 개인 조건까지 일괄 중지하지 않는다.
- 매장은 공급자 장소 ID와 내부 고정 ID로 연결한다. 이름만 같은 지점을 자동 병합하지 않는다. 공급자 변경·이전·폐점은 주소·좌표·근거를 확인한 뒤 연결을 변경한다. 연결이 불명확하면 기존 조건을 새 지점으로 옮기지 않는다.
- 매장·도보 정보는 명시적 조회 시 갱신하고 실패 시 마지막 조회 시점을 표시한다. 캐시·보관·출처 표시는 공급 계약이 허용하는 범위만 적용한다. API 오류나 검색 누락을 폐점으로 해석하지 않는다.
- 지도 실패 중에도 개인 혜택 등록·조회는 유지한다. 지도·계정 데이터와 알림 장애는 상태를 분리해 안내한다.

## 17. 확장 경계

우선 확장은 OCR·앱 알림 기반 입력 보조다. 향후 추출한 정보는 후보값으로 제시하여 같은 확인·저장 흐름에 연결한다. 운영체제마다 가능한 범위는 별도 검증한다.

그 밖의 확장은 추천·혜택가치 비교, 브랜드 행사, 동선, 지점 맛 정보, 개인카페 특징 검색, 타 업종, 즐겨찾기 매장, 계정 연결, 앱 내 도보 경로, 브랜드 추가다. 브랜드 공식 API 자동 연동, 자동 스탬프 적립, 자동 쿠폰 사용·차감, 결제, 리뷰·평점·피드, 친구/소셜도 1차 구현에 포함하지 않는다. 현재의 선호 브랜드 정렬은 즐겨찾기 매장과 다르며 MVP에 포함된다.

| 앱 계정·배포 | 개발 담당이 소셜 로그인 구성·각 스토어의 실제 제출 요구·권한 설명·계정 삭제 동작 확인 | 필요한 로그인 수단·배포 구성을 구현 설계에 추가하고 출시 전 검증. 기존 계정 자동 통합 금지 |
| 데이터 수명·보호 | 개발 담당이 계정 분리·탈퇴·백업 삭제·초안·첨부 접근·7일 오프라인 제한 검증 | 개인 데이터를 받는 공개 출시 보류 |
| 자동 처리 | 개발 담당이 19.4 시나리오와 서버 장애 후 복구·중복 방지를 검증 | 영향 자동 기능 비활성화하고 해결 후 재검증 |

프레임워크·공급자 이름·실제 요금은 본 문서로 보장하지 않는다. 이 항목은 남은 사용자 기획 선택이 아니라 담당자가 증거로 닫아야 하는 구현·조달 조건이다.

## 20. 상태 전환과 실패 시 복귀

생애·휴지통·보류는 독립 축이다. 표의 행동은 본인 소유·최신 버전·입력 검사를 통과한 경우만 허용한다.

| 대상/현재 상태 | 행동 | 다음 상태·수량 영향 |
| --- | --- | --- |
| 쿠폰 보유 | 실제 사용 기록 | 사용 완료, 스탬프 불변, 예정 취소 |
| 쿠폰 보유 | 확인 만료일 경과/실제 만료 확인 | 만료, 스탬프 불변 |
| 쿠폰 보유·예상일 경과 | 날짜 경과 | 보유+만료 확인 필요, 자동 만료 없음 |
| 쿠폰 사용 완료 | 사용 취소 | 날짜 재평가 후 보유/만료, 스탬프 불변 |
| 쿠폰 만료 | 잘못된 날짜 수정 | 확인 미래/무기한이면 보유, 예상·미확인이면 해당 확인 상태의 보유, 확인 과거면 만료 유지 |
| 쿠폰 보유/사용/만료 | 일반 삭제/복원 | 생애 보존+휴지통 이동 / 이전 생애와 날짜 재평가, 전환 취소 아님 |
| 전환 연결 쿠폰 | 전환 취소 | 전환 취소 이력, §8.4에 따른 개별 수량 평가 |
| 쿠폰 전환 취소 | 날짜 수정 | 전환 취소 유지. 다시 보유로 만들려면 실제 보유를 확인해 별도 등록 |
| 스탬프 유효 묶음 | 일부 보류 | §7.4.1 분할, 잔액 불변 |
| 보류 묶음 | 사유 하나 해소 | 다른 사유 있으면 보류 유지. 구성 확인 없이 과거 묶음 활성화 금지 |
| 유효 묶음·보류 없음 | 확인 날짜 만료 | 미반영 잔여 수량 차감, 소진 이력 |
| 만료 차감 묶음 | 오류 복구 | §7.5 확인 후 정확한 미복구 수량만 복구. 재활성 수량에는 새 만료 주기 |
| 잔액 휴지통 | 복원 | 공식 현재 잔액 확인, 같은 단위 하나로 정리, 옛 수량 합산 없음 |
| 모든 수정 화면 | 충돌/결과 불명 | 입력 보존. 최신값 비교 또는 기존 요청 결과 조회 후 재시도 |

확인 시각은 미래 입력을 차단한다. 과거 시각은 확인 사건으로 보관하되 현재의 최신 공식 확인 시각보다 오래된 사건으로 최신 확인 표시를 후퇴시키지 않는다. 과거에 본 숫자가 지금도 같다고 확인하지 못하면 현재 잔액 맞추기를 완료하지 않고 초안으로 유지한다.

미확인 프로그램의 혜택으로 지도에 진입하면 브랜드 후보를 보여주고 프로그램·적립/사용 여부는 미확인으로 표시한다. 확인된 프로그램을 임의 선택하거나 모든 후보를 사용 가능으로 표시하지 않는다.

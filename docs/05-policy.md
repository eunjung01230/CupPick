## 0. 문서 역할·번호

POL01~POL26은 제품 판단·한도·예외 규칙이다. 01의 P1~P5는 **문제 번호**이므로 정책 번호로 재사용하지 않는다. 데이터는 D01~D22, 요구사항은 R01~R69, 기능은 F01~F35다.

현재 범위는 01, 사용 흐름은 02, 사용자 요구는 03, 기능 계약은 04, 정책은 05, 저장 의미는 06이다. 문서 간 충돌을 발견하면 번호가 큰 문서를 자동 우선하지 않고 00에 근거를 남겨 함께 수정한다. 이번 정리는 기존 수치·범위를 바꾸지 않는다.

운영 기본값의 출처는 00의 D01~D09(위임결정 번호)다. 이는 06의 데이터 D번호와 **문서 경로를 붙여 구분**한다. 예: `00-D01` 파일럿 기본값, `06-D01` 계정 데이터. 본 파일에서 단독 D번호는 06을 뜻한다.

## 2. 정책 상세

### POL01. 범위·주체·공식 기록의 경계

근거: 01 §1·8; 02 §1·17 · 적용: F01·F06·F19·F25·F35

1. Android·iOS에서 주변 카페와 개인 보유 혜택을 연결해 직접 선택하도록 한다. 자동 추천·주문·결제·실제 쿠폰 발급/사용·공식 잔액 실시간 동기화는 제공하지 않는다.
2. 1차 구현 7개 대상 브랜드의 수동 기록을 허용한다. 매머드는 상위 브랜드 하나, 커피/익스프레스는 별도 프로그램으로 관리한다. 다른 종류·용도·지점 잔액도 합산하지 않는다. 브랜드 목록과 프로그램 유형은 POL26을 따르며 브랜드 추가는 후순위다.
3. 미등록을 0으로 취급하지 않고 날짜·매장·과거 이력·캡처를 모른다고 등록을 막지 않는다. 금액권 부분사용·기프티콘 전용 연동은 후순위다.
4. 보유 행사 쿠폰 직접 등록은 현재 범위이고 외부 행사 수집은 후순위다. 운영 검증은 별도 소비자 관리자 화면을 뜻하지 않는다. 후순위·변경 이력은 00을 따른다.

### POL02. 비로그인·인증·계정 분리

근거: 02 §3·5·15.4 · 적용: F01·F04·F30

1. 비로그인은 지도·주변 카페 목록·브랜드·매장명·예상 도보 시간·기본 매장 정보·지도 이동·외부 지도 길찾기를 이용한다. 내 스탬프, 내 쿠폰, 혜택 등록, 내 혜택 기준의 사용 가능 여부 판정, 개인 데이터 관리는 로그인 필요다. 비로그인 화면에 혜택 판정 배지·잔액 요약을 표시하지 않는다. 혜택 등록·선호 설정은 로그인 후에도 선택이다.
2. 구글/네이버/카카오는 제공자별 계정이다. 로그인 식별은 제공자+제공자 사용자ID 조합이며 이 조합이 다르면 다른 계정이다. 같은 이메일이라는 이유로 계정을 자동으로 연결하거나 병합하지 않는다. 이메일은 병합 키가 아니다. 로그인 성공은 요청 화면 복귀, 취소/실패는 개인 데이터 생성 없이 둘러보기로 복귀한다.
3. 모든 개인 자료 조회·변경·첨부 접근은 계정 소유권을 검사한다. 부모·자식 참조가 다른 계정을 가리키는 저장도 차단한다.
4. 로그아웃은 인증·조회 사본·발송 대상을 제거한다. 초안은 기본 보관하되 같은 계정 재인증 전 접근 금지, 선택 시 함께 삭제한다.
5. 계정 연결(제공자 간 통합)은 확장이며 현재 범위가 아니다(00 §1). 도입하더라도 사용자가 직접 휴대폰 본인인증을 마치고 연결 대상 계정들의 인증된 번호가 같다고 확인된 경우에만 연결·병합할 수 있다. 시스템이 스스로 연결하지 않으며 이메일·이름·프로필 일치는 연결 근거가 되지 않는다. 휴대폰 본인인증 기능 자체도 현재 범위가 아니다.

### POL03. 조회 위치·매장 탐색 범위

근거: 02 §3·4 · 적용: F02·F03

1. 복원할 화면 없는 새 실행은 현재 위치를 시도한다. 외부 앱/백그라운드 복귀·화면 복원은 보던 조회 위치를 유지한다. 권한 거부/위치 실패는 마지막 위치와 기준 표시 또는 직접 지정으로 처리한다.
2. 탐색 범위는 도보 15분과 30분 두 단계다. 기본값은 15분, MVP 최대는 30분이며 그보다 넓은 범위는 제공하지 않는다. 지도 영역 재조회는 허용하고 지정 매장은 거리와 무관하게 직접 조회할 수 있다.
3. 초기 후보 반경 3km는 검색 시작점이다. 실제 경로 응답으로만 선택한 범위 안인지 판단한다. 직선거리를 도보로 환산하지 않는다.
4. 이 지역 검색을 눌러 갱신하고 20개씩 추가 조회한다. 공급자가 결과를 잘랐으면 추가 조회 안내를 표시한다. 결과 없음·조회 실패·미조회 영역을 구분한다.
5. 저장한 장소는 계정당 최대 10개다. 지도에서는 저장한 장소를 눌러 조회 위치를 바꾸는 선택 역할만 하고, 이름·위치/주소 수정과 순서 변경·삭제는 저장 장소 관리 화면에서 한다. 노출 순서는 관리 화면에서 정한 순서를 따른다. 한도에 도달하면 정리를 안내하며 기존 항목을 조용히 덮어쓰지 않는다. 방문·조회 이력으로 자동 생성하지 않는다.
6. 조회 기준으로 사용 중인 저장 장소를 삭제해도 현재 지도 좌표는 일회성 지정 위치로 유지한다. 저장 프리셋에서만 빠지며 삭제를 이유로 현재 위치로 되돌리거나 목록을 비우지 않는다.

### POL04. 도보 정보·외부 길찾기

근거: 02 §4·11.3 · 적용: F03·F05

1. 도보 시간→도보 거리→매장명→고정 ID순 정렬한다. 도보 정보 없는 후보는 미확인 그룹으로 뒤에 둔다. 조회 후보 간 정렬이며 전체 매장 최단순이라고 표현하지 않는다.
2. 도보 값은 예상치이며 영업·실제 이동·혜택 사용을 보장하지 않는다. 실패해도 매장은 유지한다. 실제 경로 선은 앱 안에 표시하지 않는다.
3. 외부 길찾기는 출발/도착을 보여주고 현재 위치 출발로 변경할 수 있다. 첫 지도 앱 선택을 기억하고 변경을 허용한다.
4. 미설치/연결 실패는 다른 앱/웹 지도로 안내한다. 선택 출발지 전달 미지원은 수동 입력을 알리고 출발지를 조용히 바꾸지 않는다.

### POL05. 브랜드 카드·정렬

근거: 02 §6 · 적용: F06·F07

1. 카드에는 분리 잔액·보유 쿠폰 수·만료 요약을 표시한다. 모든 등록 잔액 0·보유 쿠폰 0이면 기본 목록에서 숨기되 등록한 브랜드 전체에서 접근을 유지한다. 거리 표시·거리 정렬은 없다.
2. 기본 만료임박순은 오늘을 포함한 가장 가까운 미경과 날짜다. 확인/예상을 함께 정렬하고 같은 날짜면 확인 우선, 이후 브랜드명·고정 ID순이다.
3. 지난 예상 날짜는 보유·확인 필요로 남기고 다음 유효 날짜를 정렬에 사용한다. 날짜 없음·무기한은 뒤에서 서로 상태를 구분한다. 구성/전환 보류 날짜는 정렬 근거에서 제외한다.
4. 선호순은 지정 순서 뒤 미지정 브랜드를 만료순으로 둔다. 선호없음은 만료순과 같고 설정 강제 없음. 마지막 정렬 선택을 기억하며 주변 매장 유무는 카드 노출·순서에 영향 없음.

### POL06. 잔액 식별·수량 불변식

근거: 02 §7.1·7.4 · 적용: F08·F09

1. 활성 잔액은 계정+브랜드+프로그램+용도+적립범위(공통/특정지점)로 식별한다. 알려진 같은 단위의 중복 활성 잔액은 만들지 않고 기존 수정으로 연결한다.
2. 프로그램/용도/범위를 모르면 별도 미확인 식별자로 저장한다. 미확인끼리 같다고 합치지 않는다. 후속 구분 시 같은 활성 단위가 있으면 공식 현재 잔액 하나로 정리한다.
3. 현재 잔액은 0 이상 정수, 적립추가는 양의 정수다. 유효한 묶음 잔여수량 합계는 잔액 이하여야 한다. 차이는 구성 미확인 수량이다.
4. 하나의 스탬프에 날짜·매장을 속성으로 붙여 날짜별/매장별 이중 합산을 막는다. 보류된 과거 묶음은 참고이며 현재 상세 합계에 넣지 않는다. 여러 공식 적립 계정 동시 관리는 후순위다.
5. 매장 조건형 잔액은 하나의 잔액 안에 **매장별 적립 수량**을 함께 관리한다. 매장별 합계는 그 잔액의 현재 수량과 같아야 한다. 어긋나면 저장을 막고 차이를 알리며 입력을 유지한다. 매장별 수량은 만료일 묶음과 다른 축이므로 같은 스탬프를 두 축에서 이중으로 세지 않는다.
6. 단계 교환형 중 매장별 관리가 필요한 프로그램(매머드커피)은 매장마다 별도 활성 잔액이다. 서로 다른 매장의 수량을 합산하거나 하나의 교환 가능 숫자로 표시하지 않는다.

### POL07. 갱신 방식·확인 시점

근거: 02 §7.2 · 적용: F10

1. 적립추가는 이번 수량만 더하고 해당 묶음에만 날짜를 붙인다. 현재 잔액맞추기는 공식 숫자로 설정하며 쿠폰을 임의 생성하거나 반영된 감소분을 다시 차감하지 않는다.
2. 현재 잔액 확인했어요는 현재 잔액을 바꾸지 않고, 공식 확인 수량을 현재 표시 수량으로 기록하면서 실제 확인 시점도 갱신한다. 묶음·매장·날짜 확인을 대체하거나 보류를 해제하지 않는다.
3. 공식 확인·기록변경·조회 시점을 분리한다. 과거 확인 시점 입력은 허용하되 미래는 차단한다. 조회·캡처·자동 정리·적립분 추가만으로 전체 공식 잔액 확인 시점을 갱신하지 않는다.
4. 수동 수정은 잔액·이력에 반영하되 별도 자동 정리 푸시는 만들지 않는다. 오래됐다는 이유로 일반 이용 중 재확인을 강제하지 않는다. 불명확한 수량 복구의 공식 확인은 별도 보호 절차다.

### POL08. 구성 변경·복수 보류

근거: 02 §7.4·8.1·16 · 적용: F11·F16

1. 개수가 같아도 구성변경을 신고할 수 있다. 영향 묶음을 알면 그것만, 모르면 해당 잔액의 영향 가능한 기존 묶음 전체를 보류한다. 다른 잔액에는 확산하지 않는다.
2. 구성·전환·정책 등 보류 사유는 함께 남을 수 있다. 원인별로 해소하고 하나라도 남으면 해당 수량의 자동 처리·만료예정 알림을 재개하지 않는다.
3. 현재 구성을 확인하거나 오래된 만료 정보를 버리고 날짜 미확인으로 정리할 수 있다. 상세 입력을 즉시 강제하지 않는다. 과거 묶음을 추가수량처럼 복구하지 않는다.
4. 전환 여부가 모호하면 임의 쿠폰 생성/추가차감 없이 유지한다. 미발급 확인은 구성·날짜 재평가, 발급 확인은 미반영 차감만 연결한다.

POL08 보완: 부분 수량은 02 §7.4.1에 따라 자식 묶음으로 분할한다. 원 묶음과 자식을 동시에 현재 합계에 넣지 않는다. 중첩 사유는 같은 자식에 연결하고 보류 수량을 사유별로 더하지 않는다.

### POL09. 날짜 신뢰·계산·경계

근거: 02 §7.3·9.2·16 · 적용: F12·F20

1. 날짜 신뢰는 확인됨/예상/미확인/확인된기간 제한 없음이다. 예상/확인은 날짜값이 있고 미확인/무기한은 유효 만료날짜값이 없다. 과거 날짜 근거는 이력으로 분리한다.
2. 알려진 적립/발급일과 검증된 적용 정책으로만 예상 날짜를 계산한다. 등록일을 발급일로 간주하지 않는다. 월/고정일수·기산일포함·월말·윤년 규칙이 불명확하면 계산 보류한다.
3. 사용자가 공식 날짜를 확인한 경우만 확정으로 바꾼다. 예상상태 저장·알림은 허용하고 실제 확인을 강제하지 않는다. 캡처 첨부만으로 승격하지 않는다.
4. 한국 날짜 D는 D다음 날 00:00부터 만료다. 시작일>만료일은 오류, 사용 시각·메뉴·주문방식은 별도 조건이다. 날짜 유효를 전체 사용가능으로 표현하지 않는다.
5. 발급일(`issuedAt`)과 사용 시작 시점(`usableFrom`)을 별도로 저장한다. 브랜드에 따라 발급 직후 쓸 수 없는 경우가 있으므로 발급일을 사용 시작 시점으로 대체하지 않는다. 확정된 값은 아래와 같다.

| 브랜드·쿠폰 | 규칙 | `usableFrom` |
| --- | --- | --- |
| 빽다방 스탬프 쿠폰 | 발급 다음 날부터 사용 | 발급일 다음 날 |
| 메가MGC커피 스탬프 리워드 쿠폰 | 발급 직후 5분간 사용 불가, 5분 이후 사용 가능 | `issuedAt + 5분` |

`usableFrom`이 날짜 단위인 브랜드와 분 단위인 브랜드를 같은 필드로 다루되 표시 문구만 구분한다. 위 표에 없는 브랜드의 대기 시간은 확인된 정책이 있을 때만 값으로 저장하고, 없으면 조건 문구로만 안내한다.

6. `오늘 사용 가능`·`내일부터 사용 가능`·`N분 후 사용 가능`·`N일 남음`·`오늘 만료`·`만료` 등 모든 시간 표현은 실행 시점의 실제 한국 날짜·시각으로 계산한다. 시안·예시 문서의 특정 날짜를 시스템 기준일로 고정하지 않는다.

### POL10. 스탬프 만료·복구

근거: 02 §7.5 · 적용: F13·F14

1. 확인된 날짜·유효 구성·보류 없음·아직 반영 안 된 수량만 자동 차감한다. 최신 잔액을 재검사해 음수/일부 임의 차감을 막고, 한 번 처리·만료이력·정리요약을 연결한다.
2. 예상 경과는 확인 필요로 유지한다. 실제 만료를 확인해도 현재 잔액 반영 여부를 먼저 판단한다. 미반영 묶음이 특정되면 차감, 불명확하면 공식 현재 잔액으로 맞추고 구성 보류한다.
3. 자동 정리는 등록한 만료 정보 기준이라고 표시하고 공식 확인 시점을 바꾸지 않는다. 날짜 수정으로 즉시 차감될 경우 저장 전에 결과를 보여준다.
4. 복구는 원 사건·수량·만료조건·이후 변경을 확인한다. 정확한 미복구 수량이고 날짜가 유효/확인무기한이면 한 번 가산한다. 확인만료수량은 만료이력만 복구한다. 예상/구성 불명/반영불명은 공식 잔액맞추기로 처리한다.

### POL11. 전환 기록·차감 배분

근거: 02 §8.1·8.2 · 적용: F15·F16

1. 기준 도달은 공식 발급 확인 안내다. 실제 발급/선택교환을 확인해야 전환 쿠폰을 기록한다. 쿠폰 기록과 필요한 차감은 함께 성공하거나 모두 미반영한다. 자동 발급형은 `발급된 쿠폰 기록하기`, 선택 교환형은 `공식 앱에서 교환했어요`로 경로를 나누며 하나의 교환 로직으로 통일하지 않는다(POL26).
2. 이미 차감된 공식 현재 잔액을 등록했다면 연결만 남기고 추가 차감하지 않는다. 이후 전환 확인 필요를 해소해도 이 규칙을 유지한다.
3. 공식 차감순서가 확인되면 적용한다. 모르면 알려진 만료일 가까운 순→오래된 적립일→ID순 제안만 하고 사용자 확인 후 반영한다. 미확인 수량도 표시한다.
4. 구성 모름은 공식 잔액·쿠폰 저장 후 영향 묶음 보류. 규칙·현재 잔액 모두 모르면 쿠폰 독립 기록+전환 확인 필요를 남긴다. 사용매장을 위해 과거 적립 전체를 다시 입력시키지 않는다.

POL11 보완: 독립 쿠폰의 후속 연결은 02 §8.2.1을 따른다. 기존 쿠폰 ID·생애를 유지하고 미반영 차감만 반영한다. 이미 반영됨은 사용자 확인 및 잔액 확인 사건 ID로 근거를 남긴다. 불명확하면 현재 잔액 맞추기 후 연결한다. 다른 전환에 이미 연결된 쿠폰은 재연결하지 않는다.

### POL12. 복수 쿠폰·전환 취소

근거: 02 §8.3·8.4 · 적용: F17·F18

1. 실제 발급 장수만 기록한다. 공통 입력 뒤 개별 쿠폰ID·조건·날짜·상태·차감연결로 독립 관리한다.
2. 전환 취소는 해당 쿠폰을 보유/알림에서 제외하고 연결 차감의 원 수량·날짜를 재평가한다. 한 장 취소는 다른 장을 바꾸지 않는다. 일반 쿠폰 삭제는 전환 취소가 아니다.
3. 실제 사용한 쿠폰을 전환 취소해 스탬프를 가산하지 않는다. 사용기록 자체가 잘못된 경우에만 확인 후 함께 정정한다.
4. 확인된 원 만료일 경과는 활성가산 금지. 이후 변경·배분불명·원잔액삭제·연결 근거 소실은 공식 현재 잔액으로 맞춘다. 과거내역 삭제/복원만으로 수량을 재처리하지 않는다.

### POL13. 쿠폰 등록·중복·생애

근거: 02 §9·13 · 적용: F19·F20·F27

1. 브랜드와 구분 가능한 이름/혜택설명은 필수다. 스탬프/행사기타/모름 종류를 구분하며 날짜·매장·프로그램 상세는 모르면 미확인 저장한다.
2. 같은 브랜드·혜택·만료일은 중복의심 안내만 제공한다. 기존유지/별도추가 선택. 날짜 미확인만으로 모두 중복 취급하지 않고 휴지통 후보는 복원과 신규를 구분한다.
3. 쿠폰 생애는 보유/사용 완료/만료/전환 취소다. 휴지통 여부는 별개다. 자동 만료는 휴지통 아닌 보유 쿠폰에만 적용한다. 예상 날짜 경과는 확인 필요 보유를 유지한다.
4. 사용 완료는 실제 사용 뒤 기록하고 알림에서 제외한다. 1차 구현에서는 공식 앱과 자동 연동하지 않으므로 사용자가 직접 사용 완료 처리한다. 사용 취소·날짜 수정·휴지통복원은 이전 생애와 날짜를 재평가한다. 날짜 수정만으로 사용 완료·전환 취소·휴지통을 보유로 되돌리지 않는다.
5. 화면에 보여주는 쿠폰 표시 상태는 저장값이 아니라 생애·날짜 신뢰·사용 시작 시점에서 계산한다. 발급일과 사용 시작 시점은 별도 값이며 같은 값으로 간주하지 않는다.

| 표시 상태 | 계산 근거 |
| --- | --- |
| 기록됨 | 보유 + 만료 날짜 미확인 또는 확인된 기간 제한 없음 |
| 아직 사용 불가 | 보유 + 사용 시작 시점이 아직 오지 않음 (`내일부터 사용 가능`·`N일 후 사용 가능`·`N분 후 사용 가능`) |
| 사용 가능 | 보유 + 사용 시작 시점 도달 + 만료 전 |
| 만료 임박 | 사용 가능 + 만료일이 임박(당일·D-1·D-3 구간) |
| 사용 완료 | 생애가 사용 완료 |
| 만료 | 생애가 만료. 예상 날짜 경과는 만료가 아니라 보유+확인 필요다 |

### POL14. 매장 조건·근거·충돌

근거: 02 §10.1 · 적용: F22·F23

1. 적립범위와 쿠폰사용범위, 적립제외와 사용제외를 각각 판정한다. 보유수량·단골·매장명만으로 추정하지 않는다.
2. 입력경로는 확인공통조건/지정목록/미확인이다. 일부목록 밖은 미확인, 전체목록 확인 후에만 밖을 불가로 둔다. 전국사용+일부제외는 예외목록의 완전성까지 확인해야 나머지를 가능으로 표시한다.
3. 근거는 서비스확인공식정책/사용자개별확인/근거미확인으로 구분한다. 개인 확인은 그 개인 기록만 적용한다. 공통 정책 미확인도 개인 쿠폰 A점 확인 표시를 막지 않는다.
4. 공통·개별 충돌은 적용 대상/시행 시점/개별예외를 비교한다. 미해소는 관련조건만 확인 필요로 두고 잔액·날짜·다른조건은 유지한다.
5. 매장 조건형 브랜드(POL26)는 매장별 적립 수량이 사용 가능 판정의 공통 근거다. 쿠폰을 기록하는 시점의 매장별 수량을 그 쿠폰에 **사용 가능 매장 상태로 보존**한다. 이후 새로 적립한 스탬프로 기존 쿠폰을 재계산하지 않는다. 기록 후의 적립은 다음 쿠폰을 위한 상태로 따로 쌓고 기존 쿠폰의 보존 상태와 섞지 않는다.
6. 보존 상태의 매장 중 최소 적립 수 이상만 사용 가능이다. 미만은 사용 불가로 표시하며 부족 수량을 함께 보여준다. 보존 목록에 없는 매장은 불가가 아니라 미확인이다. 보존 상태 자체가 없으면 그 쿠폰의 매장 조건은 전체 미확인이며 임의로 가능 판정하지 않는다.

### POL15. 매장 연결·폐점·혜택 지도

근거: 02 §10.2·11·16.1 · 적용: F24·F25

1. 공급자 장소ID와 내부ID로 같은 지점을 관리한다. 이름만으로 병합하거나 이전·폐점 매장의 개인 조건을 새 지점에 옮기지 않는다.
2. 검색 실패는 직접 매장명+지도연결전 저장을 허용한다. 연결 전 특정 지도 매장의 가능판정은 금지한다. 검색 누락을 폐점, 폐점을 혜택 소멸로 처리하지 않는다.
3. 스탬프는 주변적립매장, 쿠폰은 주변사용매장으로 연결한다. 기준혜택·프로그램·만료 정보를 표시하고 선택변경 시 목적별 가능/미확인/불가를 갱신한다.
4. 지도진입 시 최신 혜택상태를 확인한다. 사용/만료/삭제된 혜택은 활성 연결을 해제하되 일반탐색은 허용한다. 범위 밖 지정매장도 직접 열 수 있다.

### POL16. 예정 알림·자동 정리 요약

근거: 02 §12 · 적용: F26

1. 확인/예상 날짜의 D-3·당일 한국 08시에 만료예정을 안내한다. 휴지통 아닌 보유 쿠폰·유효하고 보류없는 스탬프만 대상이다. 무기한·미확인 날짜·보류·사용·만료·전환 취소·휴지통 예정은 제외한다.
2. 만료예정과 아직 안내하지 않은 자동 정리 결과를 계정당 하루요약 하나로 묶고 안에서 구분한다. 예상은 예상표시. 모두없으면 빈 푸시 없음. 단일상세/복수목록으로 연결한다.
3. 08시 이후 끝난 자동 정리 결과는 다음 날 요약에 포함한다. 장애로 놓친 만료예정을 소급하지 않는다. 앱내 상태는 현재 값으로 갱신한다.
4. 수신을 켠 로그인 기기마다 같은 요약의 발송 항목을 하나 생성하고 POL17에 따라 전달한다. 앱내 요약·확인상태는 계정에 하나. 권한 거부/푸시끄기는 앱내조회·자동 정리를 막지 않는다. OS의 정확한 수신시각은 보장하지 않는다.

### POL17. 예약 재계산·발송 중복 방지

근거: 02 §12.2·15.1 · 적용: F26·F33

1. 등록·날짜 변경·복원은 미래에 남은 일정만 생성한다. 사용·삭제·무기한/미확인 전환은 관련 미래예약 취소. 캡처교체는 예약 영향 없음.
2. 같은 날짜·같은 혜택의 예정 알림을 날짜 수정/재시도로 반복하지 않는다. 실제 발송 직전에 최신 상태·계정·기기 수신여부를 다시 검사한다.
3. 계정+한국 날짜 요약, 요약+기기 발송을 각각 중복 방지한다. 결과 불명 재전송을 새 사건으로 만들지 않는다. 예정 알림과 자동 정리 결과의 처리식별자는 구분한다.
4. 로그아웃/탈퇴 기기는 즉시 대상 제외. 이미 OS에 전달된 알림을 완전히 회수했다고 주장하지 않고 진입 시 최신상태로 보호한다.

POL17 전달 보완: 앱 내 요약 고유성과 실제 푸시 수신 횟수를 구분한다. 최초 08:00 이후 명확한 미접수·일시 실패만 1분/5분/15분 뒤 최대 3회 재시도하며 당일 08:30에 종료한다. 각 시도 전 최신 대상과 수신 설정을 다시 검사한다. 결과 불명이면 우선 제공자의 접수 결과를 조회한다. 확인 불가 시 제공자가 동일 키의 중복 제거를 보장하는 근거가 있을 때만 그 키로 재시도한다. 그런 근거가 없으면 결과 불명으로 종료하고 앱 내 요약을 유지한다. 영구 오류·기한 경과는 재시도하지 않는다. OS 실제 수신·표시 횟수를 보장하지 않는다.

### POL18. 삭제 종류·휴지통

근거: 02 §14.1·14.2 · 적용: F28·F29

1. 삭제 전 대상·개수·영향·기한을 표시한다. 과거내역삭제는 잔액불변, 만료 정보삭제는 수량유지/날짜 미확인, 잔액등록삭제는 해당잔액/묶음만 휴지통이며 발급쿠폰·다른잔액은 유지한다.
2. 쿠폰삭제는 전환차감 취소가 아니다. 캡처삭제/교체도 잔액·상태·확인 시점·알림을 바꾸지 않는다. 부모가 활성인 과거 내역을 삭제했다고 부모 알림을 취소하지 않는다.
3. 사용자 삭제는 기본적으로 삭제시각부터 60×24시간 보관(휴지통 사진 선택 영구 삭제는 POL20 예외), 그 시각 전에만 복원한다. 취소·복원시도만으로 기한을 연장하지 않는다. 휴지통은 활성·알림·합계 제외다.
4. 부모와 연결첨부는 함께 이동/복원한다. 먼저 독립 삭제한 첨부는 부모 복원으로 부활하지 않는다. 부모영구 삭제면 종속첨부도 제거한다.

### POL19. 복원 충돌·일반 이력 수명

근거: 02 §14.2·14.3 · 적용: F18·F29

1. 같은 잔액을 새로 등록했으면 과거 8+현재 5를 13으로 합산하지 않고 공식 현재 잔액 하나로 정리한다. 신규가 없어도 삭제기간 실제변동이 가능하므로 잔액복원은 공식 현재 값 확인이 필요하다.
2. 과거 묶음·날짜정보 복원은 현재 구성·반영상태와 맞는 정보만 활성화한다. 이미 사용/차감된 묶음을 다시 가산/차감하지 않는다. 불명확하면 복원보류 또는 날짜 미확인 유지다.
3. 활성 잔액/보유 쿠폰은 계정유지 중 보관한다. 사용/만료/변경 일반 이력은 사건후 365일,30일전 안내 후 정리하며 추가 60일휴지통은 없다. 사용자 삭제 휴지통은 별도 60일을 우선하며 휴지통 사진의 선택 영구 삭제는 POL20을 따른다.
4. 기한지난 일반 이력을 휴지통에서 복원하면 30일 조회유예를 둔다. 이력 정리 후 사건취소는 제공하지 않으며 현재 잔액맞추기는 가능하다. 활성 연결에 필요한 최소 사건근거만 남기고 삭제한 이미지/설명은 유지하지 않는다.

### POL20. 첨부 형식·용량·실패

근거: 02 §9.4·14.3 · 적용: F21

1. 기록당활성 3장, 장당 10MB, 계정전체 300MB(활성+휴지통)다.80%에서 안내하며 초과 시 새첨부만 막고 텍스트저장·삭제·복원은 허용한다.
2. JPEG/PNG/WebP 저장. HEIC는 지원 변환을 거친 JPEG, 실패면 재선택이다. 교체 전 파일은 휴지통이므로 용량 계산에 포함한다.
3. 파일첨부는 선택이며 확인보조다. OCR·공식사용수단·날짜/잔액/조건확인을 대신하지 않는다. 실패는 재시도 또는 첨부없이저장을 제공한다.
4. 업로드 완료·부모연결 성공 전 첨부가 저장됐다고 표시하지 않는다. 연결되지 않은 임시전송물은 재시도에 필요한 동안만 유지하고 해당 작업 취소/만료 시 정리한다. 첨부는 부모와 같은 접근권한을 따른다.

POL20 복원·영구 삭제 보완: 02 §14.2.1에 따라 복원할 사진을 선택하며 활성 3장 제한을 원자적으로 검사한다. 미선택 사진은 원래 기한으로 보관한다. 휴지통 사진의 선택 영구 삭제는 대상·복원 불가 최종 확인 후 수행하며 실제 객체 삭제 성공 후 용량을 반환한다. 처리 중 사진은 복원/첨부 연결을 차단한다. 실패는 재시도 가능 상태로 남기고 성공했다고 표시하지 않는다. 활성+휴지통+업로드 예약 바이트로 동시 업로드 한도를 검사한다. 예약은 성공 연결 시 실제 바이트로 전환하며 취소·만료 시 해제한다.

### POL21. 초안 보관·이어쓰기

근거: 02 §15.3 · 적용: F32

1. 초안은 작성기기+계정에만 보관한다. 신규작업당 1개/기존대상당 1개, 최대 20건, 마지막편집후 30일, 만료 7일전 앱내안내다. 저장 성공 시 해당초안 삭제, 실패는 유지다.
2. 초안첨부는 3장/10MB 규칙과 기기·계정당 100MB를 적용한다. 확정저장 때 계정서버한도를 다시 검사한다. 한도초과로 오래된 초안을 조용히 덮어쓰지 않는다.
3. 저장 전 잔액·쿠폰·알림·확정이력에는 반영하지 않는다. 버리기를 제공한다. 로그아웃 기본유지와 재인증 접근조건은 POL02다.
4. 이어쓰기 저장 전 최신 버전·생애·휴지통을 검사한다. 휴지통대상은 복원 먼저, 영구 삭제는 신규/중복검사, 상태 변경은 허용수정만 반영하며 초안으로 상태를 되돌리지 않는다.

### POL22. 오프라인 사본·계정 탈퇴

근거: 02 §5·14.3·15.2·15.4 · 적용: F30·F31·F32

1. 오프라인은 마지막 온라인인증후 7일 이내 같은 로그인 계정의 마지막기록 조회만 허용한다. 조회 시점·오프라인표시를 붙이고 사본없음은 연결안내,7일경과는 재인증이다.
2. 확정저장은 온라인이다. 사본·초안은 계정별 보호 저장소에 두고 일반기기 백업에서 제외한다. 재설치/기기분실 초안복구를 보장하지 않는다.
3. 탈퇴는 온라인 최종확인 후 즉시접근 차단·현재기기사본/초안삭제, 개인 본문·첨부 등 운영 자료는 24시간 안에 제거한다. 백업 재등장 차단을 위한 최소 식별자는 §4.2에 따라 최대 30일 보관한다. 다른기기는 재연결 시 탈퇴 확인 후 제거하고 즉시원격삭제 보장 없음이다.
4. 백업은 최대 30일 순환 제거하며 복구 시 삭제 목록을 재적용한다. 탈퇴는 일반 60일복원 대상이 아니다. 외부로 따로 저장한 사용자 원본은 대상이 아니다.

### POL23. 저장 원자성·동시 수정·재시도

근거: 02 §15.1·16 · 적용: F33

1. 연결된 쿠폰/잔액/사건/배분/알림변경은 성공상태가 어긋나지 않아야 한다. 내부 트랜잭션과 예약 반영 장치는 구현에서 선택하되 사용자에게 부분 성공을 완료로 보여주지 않는다.
2. 계정+요청ID에 같은 처리결과를 연결한다. 다른 내용으로 같은 요청ID 재사용은 거부한다. 자동 만료는 대상 묶음+만료 주기 ID를 고유 키로 사용한다. 일반 수정 버전과 구분하며 날짜·설명 수정이나 작업 재시도만으로 새 주기를 만들지 않는다. 차감된 수량을 정확히 복구해 재활성화할 때 복구 사건에 연결된 새 주기를 한 번 생성한다.
3. 저장 전 대상 버전 검사, 오래된 값은 최신내용/작성내용 비교 후 재수정한다. 자정정리도 같은 잔액에 대한 동시성 규칙을 적용한다.
4. 실패/없음/결과 불명을 구분하고 입력유지한다. 결과 불명은 기존결과 확인 후 재시도한다. 지도실패가 개인 기록 기능을 막지 않는다.

### POL24. 정책 운영·매장 데이터·변경관리

근거: 02 §16.1; 00 §5 · 적용: F24·F34

1. 출시 전 운영담당자를 지정하고 공식 원문·적용 대상/시점·확인일·버전·계산 근거·예외·시험사례를 검토한다. 현재 브랜드별 수치를 이 문서가 검증한 것으로 간주하지 않는다.
2. 파일럿전 전수확인·월 1회/공지시 재검토,90일 재확인없음은 신규공통계산/판정 보류다. 개인이 확인한 날짜/조건은 별도 근거다.
3. 오류는 영향규칙·의존자동 정리를 즉시 중지하고 사용자에게 영향/현재 값확인을 안내한다. 새정책이 기존개인 기록을 조용히 덮어쓰지 않는다.
4. 매장·도보는 명시조회 시 갱신하고 실패시 마지막시점표시. 캐시/보관/출처표시는 공급 계약 범위다. 기본값 변경은 00 이력과 현재문서·제품안내를 함께 갱신한다.

### POL25. 출시·파일럿 통과 조건

근거: 02 §19 · 적용: F35

1. 도보 실제경로/매장검색·두플랫폼·표시/캐시권한·외부지도연결·계정삭제·개인 자료보호·자동 처리 인수검증을 증거로 확인한다. API 공급자·요금·프레임워크는 이 문서에서 새로 확정하지 않는다.
2. 계약별 일일비용 상한·80%경보·상한 도달 신규유료조회중지를 구현한다. 예산/계약 검증 없이 유료운영을 시작하지 않는다. 이 문서 작성은 결제/계약 실행이 아니다.
3. 위임기본값은 서현역생활권 20명 14일이다. 분석 15명 이상, 첫등록 80%/중앙 2분 이내, 재갱신 80%/중앙 30초 이내,2주차재사용 50%, 선택도움 60%, 중대오류 0을 초기판단에 사용한다.
4. 실제 만료대상 없는 사람을 알림활용률 분모에 넣지 않는다. 기준미충족은 입력부담 개선·파일럿 재검증, 중대오류는 해결 전 전국확장 보류다. 시나리오 정의를 시험통과로 표시하지 않는다.

   - **매장 조건형**: 발급은 누적형과 같다. 사용 가능 매장은 POL14.5·POL14.6에 따라 쿠폰 기록 시점의 매장별 적립 수량으로 판정한다.
   - **단계 교환형**: 자동 전환이 없다. 12개에서 아메리카노 쿠폰, 20개에서 모든 음료 쿠폰으로 사용자가 공식 앱에서 직접 교환하며, 교환하지 않고 계속 모을 수 있다. CupPick은 `공식 앱에서 교환했어요`로 선택한 단계만 기록·차감한다.
3. 매머드는 목록에서 상위 브랜드 하나로 표시하고 내부에서 매머드익스프레스와 매머드커피를 독립 프로그램으로 구분한다. 두 프로그램의 스탬프·쿠폰 기록을 섞지 않으며 매장 데이터도 어느 프로그램의 매장인지 구분한다. 매머드 일부 특수매장은 적립·사용이 제외될 수 있으므로 유의사항으로 안내한다.
4. 어떤 유형에서도 CupPick이 공식 쿠폰을 발급하거나 공식 스탬프를 차감하지 않는다. 모든 브랜드를 10개 자동 전환으로 취급하지 않고 하나의 `교환하기` 로직으로 통일하지 않는다.
5. 확정된 사용 시작 시점은 빽다방(발급 다음 날)과 메가MGC커피(발급 후 5분) 둘이며 값은 POL09.5의 표를 따른다.
6. 이 표의 값은 최종 CupPick v2 디자인과 확정된 제품 결정의 범위다. POL24의 검토 절차로 공식 원문·적용 시점을 확인하기 전까지 여기 없는 수치를 추정해 추가하지 않는다. 브랜드별 만료 기간과 차감 순서는 아직 확정되지 않았으므로 미확인으로 둔다.

### 4.2 작업 복구·정리

- 미연결 업로드 예약·객체는 생성 후 최대 24시간이다. 개별 삭제/정리 작업은 원칙적으로 3회 재시도 후 운영 확인으로 넘기지만 24시간/30일 등 삭제 기한을 연장하는 근거가 되지 않는다. 기한 내 완료되지 않으면 운영 사고로 처리한다. 연결 확정과 만료 정리는 같은 상태/버전을 검사한다. 만료 뒤 저장은 새 업로드가 필요하며 텍스트 초안은 보존한다.
- 수량·쿠폰·사건·알림 변경 의도를 같은 저장 단위로 남긴다. 큐 전달 자체가 실패해도 저장된 의도를 다시 처리할 수 있어야 한다. 알림 반영 의도도 없으면 성공으로 응답하지 않는다.
- 만료 대상은 매일 자정 처리하고 15분마다 미처리 대상을 재조회한다. 예약 시각 15분 초과 미처리를 운영 오류로 감지한다. 재처리 직전 최신 구성·보류·반영 상태를 평가하며 임의 부분 차감하지 않는다.
- 만료 예정 알림의 지난 일정은 소급하지 않는다. 늦게 완료된 자동 정리 결과는 다음 요약에 포함한다. 숫자 처리와 발송 성공을 같은 상태로 취급하지 않는다.
- 오류는 대상 사건ID·종류·발생 시각·시도 횟수·마지막 오류 분류로 남긴다. 자동 재시도 3회 후 운영 확인 대상으로 전환하되 원자료를 삭제하지 않는다. 외부 푸시에는 POL17의 별도 안전 재시도 조건이 우선한다.
- 탈퇴 후 자료 재등장을 막는 최소 삭제 식별자는 백업 제거 완료까지 최대 30일 유지한다. 24시간 삭제 대상인 개인 본문·첨부와 구분하며 백업 복원은 차단 목록 적용 후 공개한다.
